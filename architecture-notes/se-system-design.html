▸ 核心要点
1流程设计表示工具
工具全称（英文）特点 / 考点
PFD程序流程图
Program Flow Diagram		图框表示操作，由顺序、选择、循环三种结构组合嵌套；直观清晰易学，独立于语言
IPO 图输入-加工-输出图
Input-Process-Output		描述模块的输入/加工/输出三部分；数据流图 DFD 本质就是一种 IPO 图
N-S 图盒图（纳西-施耐德曼图）
Nassi-Shneiderman Diagram		取消流程线，易表示嵌套层次、结构化特征强；问题复杂时图很大，不适合复杂程序
PAD问题分析图
Problem Analysis Diagram		支持结构化程序设计（不是原型化！）；逻辑清晰、图形标准化

易混淆（真题常考）：PAD 支持「结构化」而非「原型化」；N-S 图不适合复杂流程（并非"特别适合"）；IPO 图适合流程描述。

1.1BPM vs BPR（业务流程设计分类）
BPM 业务流程管理
  • Business Process Management
  • 识别、建模、分析、优化、自动化业务流程
  • 渐进式，持续改进，关注执行/监控/优化/自动化
VS
BPR 业务流程重组
  • Business Process Reengineering
  • 根本性再思考 + 彻底性再设计
  • 激进式，追求质的飞跃，成本/质量/服务/速度显著提升

考点：BPR 核心是对流程的根本性改造，以流程为中心（不是需求/组织/资源）。流程管理三层面：规范流程 → 优化流程 → 再造流程。

什么时候用哪个图（速记）

  • 画「程序怎么一步步跑」→ PFD 程序流程图（最通用）
  • 画「一个模块的输入/加工/输出边界」→ IPO 图
  • 画「简单程序的干净逻辑、强调结构化」→ N-S 图（复杂程序别用，盒子会爆炸）
  • 画「结构化设计、分支多的程序逻辑」→ PAD 图

2概要设计 vs 详细设计
  • 概要设计：总体结构设计，功能需求分配给模块，确定调用关系，形成模块结构图 + 概要设计说明书
  • 详细设计：模块内算法、数据结构、数据库物理设计、输入输出/界面、详细设计说明书
2.1模块结构设计（扇入 / 扇出）

模块结构设计＝概要设计（总体结构设计）的核心：把功能分配给模块，确定模块间的调用关系，用模块结构图表示（矩形=模块、箭头=调用、标注=传递的数据）。衡量模块结构质量的关键指标是扇入、扇出：

扇入（Fan-in）
  • 有多少个上级模块调用我
  • 扇入大 = 复用程度高（好，如公共工具模块）
VS
扇出（Fan-out）
  • 我调用了多少个下级模块
  • 扇出过大 = 模块太复杂，应增加中间控制模块分层

口诀：多扇入、少扇出。扇出过大 → 增加中间控制层（不是把下级模块再分解）；扇入大 = 复用度高（不是复杂度高）。

3系统设计原理与原则

原理：抽象化、自顶而下逐步求精、信息隐蔽、模块独立（高内聚低耦合）。

  • 模块大小适中、减少调用深度
  • 多扇入、少扇出（扇入大=复用度高）
  • 单入口单出口、作用域在模块内、功能可预测
4内聚（低→高）

偶然 → 逻辑 → 时间 → 过程 → 通信 → 顺序 → 功能（口诀：偶逻时过通顺功）。

  • 偶然（元素无联系）· 逻辑（参数决定做哪个相似功能）· 时间（需同时执行）
  • 过程（按指定过程顺序）· 通信（操作同一数据结构）· 顺序（前一输出=后一输入）
  • 功能内聚（最高）：所有元素共同完成一个功能，缺一不可
5耦合（低→高）

无直接 → 数据 → 标记 → 控制 → 外部 → 公共 → 内容（口诀：无数据标控外公内）。

  • 数据（传简单数据值）· 标记（传数据结构）· 控制（传控制变量）
  • 外部（经软件外环境，如 I/O/协议）· 公共（共用公共数据环境）
  • 内容耦合（最差）：直接使用另一模块内部数据或非正常入口转入
◆ 费曼

内聚耦合说人话：内聚＝模块内部成员多"团结"——功能内聚像一个人专心做一件事；偶然内聚像杂货铺啥都卖。耦合＝模块之间多"纠缠"——数据耦合只递纸条（简单数据），内容耦合直接翻对方抽屉（最糟）。目标就是模块内部高内聚、模块之间低耦合。

▸ 总结

流程设计工具（PFD/IPO/N-S/PAD）选型；概要设计产出模块结构图，详细设计产出算法与数据结构；设计核心是高内聚低耦合——内聚口诀「偶逻时过通顺功」（偶然→功能），耦合口诀「无数据标控外公内」（无直接→内容）。
