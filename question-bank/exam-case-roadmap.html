P0 · 保底必拿

◆ 第一题必答 + 高频选做，务必吃透
质量属性与架构评估一模试题一 · 传统 case-quality
  • 质量属性六要素：刺激源 / 刺激 / 环境 / 制品 / 响应 / 响应度量（口诀：谁·干什么·什么环境·对啥·啥反馈·怎么量）
  • 属性分类：运行期（性能/可用性/安全性/可伸缩性/互操作性）vs 开发期（可修改性/可测试性/可扩展性/可移植性）
  • 效用树：树根 → 质量属性 → 属性分类 → 质量属性场景；场景标注优先级 (H/M/L)
  • 评估方法：SAAM / ATAM（四阶段）/ CBAM；敏感点（单属性）· 权衡点（多属性）· 风险点
  • 练习：把 (a)~(h) 快速归类到 性能 / 可用性 / 安全性 / 可修改性
对应笔记 软件质量属性全解 架构评估 SAAM·ATAM·CBAM 质量属性+架构评估
数据库 / 缓存 / 分布式一模试题四
  • Redis 三种集群模式（主从 / 哨兵 / Cluster）优缺点对比；自建集群 vs 云托管（成本/灵活性/扩展性）
  • 缓存三大问题：穿透 / 击穿 / 雪崩；热点 Key、一致性哈希、分布式锁
  • 反规范化设计方法与数据不一致解决；读写分离 / 主从复制 / 分库分表
  • 分布式事务、CAP 与 BASE 理论
对应笔记 Redis 集群与高可用 Redis 缓存三大问题 函数依赖与范式 分布式数据库与 NoSQL
微服务 / 云原生一模试题五
  • API 网关作用：统一入口 / 路由转发 / 负载均衡 / 聚合响应 / 认证授权 / 限流熔断 / 协议转换 / 缓存
  • DevOps 与 CI/CD：自动化测试、快速反馈、频繁部署、环境一致性
  • 服务治理：注册发现 / 配置中心 / 熔断降级限流 / 可观测 / 服务网格；微服务优劣势与 DDD 拆分
对应笔记 微服务架构专题 云原生架构
大数据架构补充试题二 · 2023 真题
  • Lambda 三层：批处理层 / 加速层 / 服务层；Kappa：单一流处理链路
  • 原始主数据用不可变追加式存储，保留全部历史数据
  • 架构图分层与组件：采集(Nginx/Flume/Kafka) → 集成(Sqoop/ETL) → 计算(Spark/Flink/MapReduce) → 存储(HDFS/HBase/MemSQL)
对应笔记 分布式数据库与 NoSQL 未来信息综合技术

P1 · 常考、性价比高

◆ 选做题常见，按优势选题
面向对象建模 / UML / 设计模式一模试题二
  • 用例图：包含 include / 扩展 extend / 泛化；参与者识别
  • 类图、状态图、序列图（消息、分支片段、与协作图对比）

对应笔记 OO·UML·设计模式 设计模式 23 种 GoF
非功能需求 + C/S 架构选型补充试题三
  • 非功能需求四类：操作性需求 / 性能需求 / 安全性需求 / 文化需求（含义+归类）
  • 瘦客户端 vs 胖客户端 C/S 的权衡（业务逻辑位置、运维、缓存、加密）
对应笔记 系统设计（内聚耦合/概要/详细） 软件架构风格全览 层次架构
项目管理（进度 / 成本）补充试题一
  • 关键路径与网络图；工期估算、赶工 / 加班成本权衡
  • 项目计划应包含的内容（背景、目标、进度、预算、变更流程等）
对应笔记 进度管理与关键路径 配置管理与质量风险管理
优先级

P2 · 冷门，会则答

◆ 低频／边缘化，遇陌生技术可直接放弃
嵌入式软件可靠性一模试题三
  • 系统可靠性四子特性：成熟性 / 容错性 / 易恢复性 / 可靠性的依从性
  • 提高可靠性技术：冗余 / 软件容错 / 双机容错 / 集群；串并联可靠度计算
  • 恢复块方法（主块/验证测试/异常处理，单机）vs N 版本程序设计（多机、表决）
  • 硬件 vs 软件可靠性差异（浴缸曲线 / 无老化 / 维修 / 报警）
对应笔记 软件可靠性 计算机可靠性（串并联） 嵌入式系统概述

策略

备考策略

  1. 主攻第一题：架构评估是唯一必答题，考点固定、紧贴教材，是全场最稳的送分题，优先吃透。
  2. 4 选 3 选题：第 1 题必答，其余 4 题选 2；按自身优势（后端优先数据库/分布式/云原生）选择，遇陌生技术果断放弃。
  3. 背答题模板：每个分论点按「概念一句话 → 项目问题 → 方案取舍 → 具体技术 → 量化结果」展开；结尾务必补写"不足与解决措施"。
  4. 趋势研判：前沿技术（云原生/微服务/大数据）已成主流选做；软件工程、嵌入式逐步淡化——按 P0 → P1 → P2 分配时间。
