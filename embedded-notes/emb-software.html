▸ 核心要点
1嵌入式软件按功能分类（3 类）
  • 系统软件：控制管理资源、为应用提供支持——设备驱动程序、嵌入式操作系统、嵌入式中间件。
  • 应用软件：上层软件，定义设备主要功能用途、与用户交互——飞行控制软件、手机软件、地图。
  • 支撑软件：辅助开发的工具软件——系统分析设计工具、在线仿真工具、交叉编译器。
2嵌入式软件低功耗设计（3 项技术）

低功耗设计主要技术：编译优化技术、软硬件协同设计、算法优化（口诀：编、协、算）。

  • 软硬件协同设计：软件设计与硬件匹配；编译优化：低功耗编译技术；算法优化：减少系统持续运行时间；另可用「中断」代替「查询」、电源有效管理。
3嵌入式软件开发阶段与工具

开发分几个阶段：编码 → 交叉编译 → 交叉调试。

工具作用
编辑器编写源码，如 VS、eclipse、keil、Source Insight、vim
编译器 gcc用交叉编译工具处理源码生成目标文件（GNU C/C++）
调试器 gdbGNU 程序调试工具，交叉调试
4交叉编译与交叉调试（真题高频）
  • 交叉编译：在一个平台上生成可在另一个平台上执行的代码，把相同代码翻译成不同 CPU 的二进制。开发需借助宿主机（通用计算机）编译出目标机的可执行代码。
  • 交叉调试：调试器运行在宿主机上，被调试程序运行在目标机上，通过串口、并口、网络、JTAG 等通信。

宿主机编译/调试，目标机运行——两者必须分离（调试器与被调试程序不在同一台机器）。

5嵌入式数据库系统（按存储位置 3 类）
类型全称含义
MMDB基于内存方式数据存储在内存中
FDB基于文件方式数据按格式存储在磁盘，程序直接读写数据文件
NDB基于网络方式基于 4G/5G，嵌入式设备是远程服务器的客户端
  • 使用环境特点：设备随时移动性、网络频繁断接、网络条件多样化、通信能力不对称。
  • 关键问题：数据一致性（复制性）、高效事务处理、数据安全性。
◆ 费曼

嵌入式软件开发 = 用「翻译官」在另一台机器上编代码：因为目标设备太小没法自己编译，就在宿主机上写代码、用交叉编译器（gcc）把源码「翻译」成目标机 CPU 能跑的二进制，再用 gdb 隔着串口/网络调试目标机上跑的程序。软件分三层：系统软件打底、应用软件干正事、支撑软件是工具箱；为省电要靠编译优化+软硬协同+算法优化三招。

▸ 总结

软件分类=系统/应用/支撑；低功耗 3 技术=编译优化+软硬协同+算法优化（编协算）；开发=编码→交叉编译(gcc)→交叉调试(gdb)，宿主机编译调试、目标机运行；嵌入式数据库=MMDB（内存）/FDB（文件）/NDB（网络）。
