▸ 核心要点
1三种集群方案

单节点并发能力有上限，需搭建集群提高并发与可用性。三种方案：

  • 主从复制：一主多从，读写分离（主写从读），解决高并发读、数据冗余；但主节点单点，需人工/哨兵故障转移。
  • 哨兵模式：主从 + 哨兵监控，自动故障恢复，无需人工介入；但主节点单点，写性能受限。
  • 分片集群（Cluster）：多主多从 + 数据分片，解决海量数据存储和高并发写两个问题；架构复杂、跨节点事务受限、不能用 Lua 和事务。

生产常见选择：主从（1 主 1 从）+ 哨兵即可；单节点不超 10G 内存，不够就给不同服务分配独立主从；尽量不做分片集群（维护麻烦、心跳和数据通信耗网络带宽）。

2主从同步（全量 / 增量）

全量同步（从节点第一次连接或积压缓冲区不足）：

  • 从节点携带 replicationid + offset 请求同步；主节点判断是否第一次（replicationid 是否一致）。
  • 主节点执行 bgsave 生成 RDB 发送给从节点；从节点清空自身数据后加载 RDB。
  • RDB 生成期间主节点的写命令记录到缓冲区（日志文件），最后一起发给从节点执行。

增量同步（从节点重启后数据不一致）：从节点再次请求，主节点判断非第一次，从命令日志（repl-backlog 缓冲）中取 offset 之后的数据发给从节点同步。

3哨兵模式 + 脑裂

哨兵（Sentinel）作用：①监控（每隔 1 秒 ping 各实例，检测健康）；②自动故障恢复（master 故障时选一个 slave 提升为 master）；③通知（充当客户端服务发现来源，故障转移后推送最新信息）。

  • 主观下线：某 sentinel 发现实例未按时响应则主观下线；客观下线：超过指定数量（quorum）的 sentinel 都认为主观下线——quorum 最好超过 sentinel 数量一半。
  • 选主规则：先排除与主断开过久的从节点 → 从节点 slave-priority 越小越优先 → 相同则 offset 越大越优先 → 相同则 运行 id 越小越好。
  • 脑裂：主从和 sentinel 处于不同网络分区，sentinel 心跳感知不到 master 就选了个新 master，导致两个 master（旧 master 仍在写数据），网络恢复后旧 master 被降为 slave 再同步，大量数据丢失。
  • 解决脑裂：配置最少从节点数量（没达到就拒绝写）+ 缩短主从同步延迟时间（达不到要求拒绝请求），避免大量数据丢失。
4分片集群（Cluster）

分片集群解决：海量数据存储 + 高并发写。特征：①集群有多个 master，每个保存不同数据；②每个 master 可有多个 slave；③master 之间 ping 监测健康；④客户端可访问任意节点、自动转发到正确节点。

  • 哈希槽（Hash Slot）：集群有 16384 个哈希槽，每个 key 经 CRC16 校验后对 16384 取模决定放置哪个槽，每个节点负责一部分槽。
  • 读/写：key 的有效部分（大括号 {user:1001} 内容）计算哈希取模，找槽所在实例；若不在当前节点返回 MOVED 重定向。
  • 限制：不支持跨槽多键操作（如事务、MGET）；批量操作需用 Hash Tag（{user:1001}.name 和 {user:1001}.age 同槽）。
5Redis 单线程为什么快 + IO 多路复用
  • 单线程仍快原因：①纯内存操作，C 语言编写，执行速度快；②单线程避免上下文切换和竞争条件（多线程还要考虑线程安全）；③使用 I/O 多路复用，非阻塞 IO。
  • I/O 多路复用：利用单个线程同时监听多个 Socket，某 Socket 可读可写时得到通知，避免无效等待、充分利用 CPU。
  • 实现对比：select/poll 只通知有 Socket 就绪但不确定是哪个，需遍历确认；epoll 在通知同时把已就绪 Socket 写入用户空间，效率高。
  • Redis 网络模型：I/O 多路复用 + 事件处理器（连接应答、命令请求、命令回复）；Redis 6.0 后命令请求/回复处理引入多线程，但命令执行仍单线程。
◆ 费曼

Redis 集群说人话：三个梯队——主从（一主多从，主写从读，手动切）、哨兵（派个"监工"盯主从，主挂了自动让从上位，但怕脑裂变两个 master 丢数据）、分片（多个 master 各管一段数据，靠 16384 个哈希槽 + CRC16 算 key 该放哪）。单线程为啥快？内存操作 + 不切线程 + IO 多路复用（一个线程盯着很多 socket），跟"一个人同时盯很多个电话，哪个响接哪个"一个道理。

▸ 总结

集群三方案主从/哨兵/分片：主从解决高并发读（全量同步 RDB + 增量同步 offset 偏移量）；哨兵自动故障转移（监控/通知/故障恢复）、选主看priority→offset→runid、防脑裂；分片用 16384 哈希槽 + CRC16（跨槽不能用事务/Lua）；单线程快因纯内存+不切线程+IO 多路复用(epoll)。重点应对集群选型与脑裂题。
