▸ 核心要点
1什么是 Redis + 核心特性

Redis（Remote Dictionary Server）：开源的、基于 Key-Value 结构的 NoSQL 内存数据库，支持网络、可持久化、具有丰富数据结构。核心定位：作为客户端与持久化数据库（MySQL）之间的缓存层——减少数据库 IO 压力、提升访问速度（内存比磁盘快 10~100 倍）、支持高并发。

  • 高性能：纯内存操作，读写可达 10 万+ QPS（缓解数据库压力）。
  • 丰富数据结构：String/Hash/List/Set/ZSet 等（按业务选结构）。
  • 持久化：RDB 和 AOF 两种机制（平衡性能与可靠性）。
  • 高可用：主从复制、哨兵、Cluster 集群（故障转移、避免单点）。
  • 原子性操作：单线程执行命令天然原子，多条指令用 Lua 脚本保证原子性。

33 种特殊类型 + 通用命令
  • Geospatial（地理空间）：存地理位置、算距离/范围 → 附近的人、门店距离排序。

主从复制原理：全量同步（从节点首次连接或积压缓冲区不足时，主节点生成 RDB 发送给从节点）；增量同步（主节点把写命令写入 repl-backlog 缓冲区，从节点按偏移量获取增量命令）。主从实现读写分离和数据冗余，但主节点单点故障需人工或哨兵自动转移。

◆ 费曼

Redis 说人话：就是给 MySQL 前面加一个「超快的备忘录」——数据先查 Redis（内存，快 10~100 倍），查不到才回源 MySQL。五种数据类型记场景：String 存字符串（缓存/锁）、Hash 存对象（购物车）、List 存列表（消息队列）、Set 存去重集合（抽奖/共同好友）、ZSet 存带分排序（排行榜）。特殊三兄弟：Geo 管地理位置、HyperLogLog 统计 UV、Bitmap 按位存签到。记住 `keys *` 生产禁用（会阻塞主线程）。

▸ 总结

Redis＝基于 K-V 的 NoSQL 内存数据库，作 MySQL 缓存层；核心特性高性能(10万+QPS)/丰富结构/持久化/高可用/原子性；5 类型String/Hash/List/Set/ZSet + 3 特殊Geo/HyperLogLog/Bitmap；部署 4 式单机/主从/哨兵/Cluster。主从复制分全量同步(RDB)+增量同步(repl-backlog 偏移量)。重点应对数据类型选型题。
