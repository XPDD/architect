▸ 核心要点
1RDB vs AOF 对比
特性RDB（数据快照）AOF（追加日志）
机制指定时间间隔把内存全量数据生成二进制快照（dump.rdb）记录所有写操作指令到文本日志（appendonly.aof），重启重放指令恢复
文件体积压缩二进制、体积小纯文本、体积大（可重写压缩）
恢复速度快（直接加载二进制）慢（需逐条执行命令）
数据安全可能丢失最后一次快照后数据按刷盘策略可做到秒级/实时（最多丢 1 秒）
性能影响fork 子进程、有短暂阻塞持续写入，fsync 策略影响性能
适用场景容灾备份、数据完整性要求不高（缓存）数据完整性要求高、不能接受丢失（计数/订单）

选型：高性能可接受少量丢失→仅 RDB；数据安全→仅 AOF(everysec)；生产环境最优解＝RDB+AOF（RDB 做全量快速恢复 + AOF 做增量补充）。混合持久化（Redis 4.0+）：AOF 文件前半段是 RDB 全量、后半段是 AOF 增量日志，结合快速恢复和低丢失。

2RDB 执行原理 + AOF 刷盘策略

RDB 执行原理（bgsave）：bgsave 开始时 fork 主进程得到子进程，子进程共享主进程内存数据，完成后读取内存数据写入 RDB 文件。采用 copy-on-write（写时复制）：主进程读操作访问共享内存；写操作则拷贝一份数据再写，互不影响。

  • AOF 刷盘策略：Always（同步刷盘，可靠性高几乎不丢数据但性能影响大）；everysec（每秒刷盘，性能适中、最多丢 1 秒——默认/较优）；no（操作系统控制，性能最好但可能丢大量数据）。
  • AOF 重写（bgrewriteaof）：合并同一 key 的多次写为最后一次，用最少命令达到相同效果，避免文件过大。
3过期删除策略
  • 惰性删除：不主动检查，只有当客户端访问该 key 时才检查是否过期，过期则删。优点极度省 CPU；缺点浪费内存（一直没人访问就一直占）。
  • 定时删除：设过期时间时创建定时器，到点立刻删。优点内存利用率极高；缺点极度消耗 CPU（高并发会阻塞主线程），Redis 几乎不用。
  • 定期删除：每隔固定时间（默认 100ms）随机抽取一部分带过期时间的 key 检查删除。优点折中性价比最高；缺点有少量过期键漏清。
  • Redis 实际做法：惰性删除 + 定期删除配合——日常靠定期删除批量清理，零散靠惰性删除兜底；都清理不掉时内存满了触发淘汰策略（LRU）。
4内存淘汰策略

触发：Redis 先执行"惰性删除 + 定期删除"清理过期 key，如果内存仍达 maxmemory 上限，就触发内存淘汰策略（最后一道内存保障）。

  • LRU（最近最久使用）：淘汰访问时间最旧的数据（当前时间-最后访问时间，值越大越淘汰）。
  • LFU（最近最少使用）：淘汰访问频率最低的数据（统计访问频率，值越小越淘汰）。
  • 分两类范围：volatile-xxx（只淘汰设了过期时间的 key）、allkeys-xxx（淘汰所有 key）。
策略核心逻辑适用场景
volatile-lru淘汰过期键中最近最久未用的90% 生产场景（有核心永久数据）
allkeys-lru淘汰所有键中最久未用的纯缓存场景（数据可重建）
volatile-lfu淘汰过期键中访问频率最低的资讯/电商（按热度排序）
noeviction不淘汰，写请求报错金融/支付（数据绝不能丢，Redis 默认）

使用建议：优先 allkeys-lru（有冷热数据区分时）；数据访问频率差别不大用 allkeys-random；有置顶需求用 volatile-lru（置顶不设过期）；短时高频访问用 lfu。Redis 默认 noeviction（内存不足写入报 OOM，读不受影响）。经典问答：DB 1000 万数据、Redis 只缓存 20 万且要留热点 → 用 allkeys-lru。

◆ 费曼

Redis 持久化说人话：RDB 就是"定期拍全家福"——把当前所有数据存成一张快照照片（体积小、恢复快，但两次拍照之间丢的数据补不回）；AOF 是"写日记"——每一条写命令都记下来，坏了就重新念一遍日记恢复（不丢数据但慢）。所以聪明做法是RDB 拍照 + AOF 日记一起开（混合持久化）。过期删除三种策略：懒人式（惰性删除，用到才查）、自爆式（定时删除，费 CPU 几乎不用）、抽查式（定期删除，性价比最高）；Redis 实际是懒人+抽查混用，兜底再靠 LRU 汰旧。

▸ 总结

RDB（快照，体积小、恢复快、可能丢数据)、AOF（日志，体积大、恢复慢、几乎不丢）；生产环境 RDB+AOF 混合；RDB 用 fork+copy-on-write，AOF 刷盘always/everysec/no 三档；过期删除惰性 + 定期；内存淘汰 8 种，常用allkeys-lru（留热点）、volatile-lru（有永久数据）、默认 noeviction。重点应对 RDB/AOF 对比与淘汰策略题。
