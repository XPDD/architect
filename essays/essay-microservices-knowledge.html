分论点一：服务拆分（解耦）

SPLIT
名词 · TERM是什么 · WHAT为什么 · WHY解决什么问题 · PROBLEM SOLVED
微服务架构Microservices 把单体拆成一组独立部署、独立演进的小服务，服务间通过网络通信 单体耦合重、无法独立伸缩/发布 独立部署与扩展、故障隔离、技术异构
DDD 领域驱动拆分Domain-Driven Design 按业务领域边界拆（用户/订单/支付域），每个域一个服务 按代码/技术拆会导致边界混乱 单一职责、低耦合、领域自治（论题一 2025.11 考点）
拆分取舍Trade-off 独立演进/弹性 vs 运维复杂度/分布式复杂度 不是拆得越多越好 适度拆分 + 治理兜底

分论点二：服务治理（注册/配置/网关）

GOVERNANCE
名词 · TERM是什么 · WHAT为什么 · WHY解决什么问题 · PROBLEM SOLVED
注册发现Nacos / Eureka服务启动注册到注册中心，消费者按服务名查 IP/端口实例 IP 动态变化，硬编码失效服务地址动态发现、心跳健康检查、异常实例剔除
配置中心Apollo / Nacos配置统一托管，动态下发改配置要重发版，慢且易错动态配置、免发版切换（日志开关/限流阈值）
API 网关Gateway所有流量的统一入口：路由、鉴权、限流服务直连导致横切逻辑分散统一收敛鉴权/限流/灰度，屏蔽内部服务结构
负载均衡Load Balancing把请求分发给多个实例（Ribbon/网关 LB）多副本需要分发策略分摊压力、避免单点过热

分论点三：容错与可观测（雪崩防护）

RESILIENCE
名词 · TERM是什么 · WHAT为什么 · WHY解决什么问题 · PROBLEM SOLVED
熔断Circuit Breaker · Hystrix依赖服务故障时快速失败返回备选，别死等依赖挂了会拖垮调用方（雪崩）别人坏了我不等，防雪崩，论文最亮技术点
降级Fallback / Degradation高峰时主动砍掉非核心功能，返回兜底结果资源有限，保核心业务我主动砍功能，保证核心链路可用
限流Rate Limiting · Sentinel限制单位时间请求量（令牌桶/漏桶）流量洪峰打爆系统进门限量，平滑流量保护后端
分布式事务Seata / TCC跨服务的最终一致性（两阶段/TCC/消息）一个业务跨多个库/服务数据一致性（写不出时可不展开）
异步解耦Kafka / RabbitMQ消息队列削峰填谷、事件驱动同步调用耦合强、峰值硬扛异步解耦、削峰、可重试
可观测性SkyWalking / Three Pillars链路追踪 + 日志 + 指标调用链跨服务，故障难定位全链路追踪、根因定位
服务网格 / K8sIstio / Kubernetes网格把连接/安全/流量下沉基础设施；K8s 做编排SDK 侵入强 / 部署要统一零侵入治理；弹性伸缩、自愈、自动交付
✦ 口诀 · MEMORY RHYME

熔断"别人坏了我不等" · 降级"我主动砍功能" · 限流"进门限量"。
Breaker: don't wait on a failing dependency · Fallback: I proactively cut features · Rate limit: control the entrance.
