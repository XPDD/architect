▸ 核心要点
1四类数据模型 + 三要素
模型要点
概念模型从用户角度建模，现实世界→信息世界的第一抽象，真正的实体-联系模型
关系模型用二维表表示实体-联系，由 E-R 模型转换而来
网状模型表示实体及联系，一事物和多事物有联系，形成"网"
面向对象模型以对象为单位，含属性+方法，有类、继承特点

三要素：数据结构（对象类型集合）、数据操作（对象实例允许的操作）、数据约束条件（完整性规则集合）。

2E-R 图三要素符号（必记）
  • 椭圆 = 属性（一般省略）；长方形 = 实体；菱形 = 联系，联系两端填写联系类型（1:1 / 1:N / M:N）。
  • 实体：客观存在可相互区别的事物。弱实体依赖强实体而存在（如"家长"依赖"学生"）。实体集：同类型同属性的实体集合（学生、课程）。
  • 属性分类：简单/复合；单值/多值；NULL；派生属性（可由其他属性运算得出，如年龄←出生日期）。域=属性取值范围。码 key=唯一标识实体的属性集。
3E-R 转关系模型（高频考点）
联系类型转换规则主键
1:1联系可放入任意一端实体作属性（保证两端关联），或单独一个关系模式任一端主键
1:N联系可单独成关系模式，或在 N 端实体加入 1 端实体的主键N 端主键
M:N联系必须单独作为一个关系模式M、N 端的联合主键
⚠ 记忆口诀："一对一随便放，一对多放多端，多对多必须拆"。M:N 联系单独成表，主键是两个实体主键的组合。
◆ 费曼

E-R 图是"白板上的草图"，关系模型是"能存进数据库的表"。转换时：每个实体→一张表；联系怎么处理看类型——1:1 的联系信息塞进任一方即可；1:N 的联系把"1"那方的主键塞到"N"那方当外键；M:N 联系没法塞进任何一方，只能单独建一张"中间表"，主键就是双方主键拼起来。

◆ 逻辑关系 — E-R 转关系模型
实体 → 关系模式  ·  属性 → 字段  ·  码 → 主键
1:1 放任一端 / 单独  |  1:N 放 N 端 / 单独  |  M:N 必须单独（联合主键）

▸ 总结

数据模型三要素=数据结构+数据操作+约束条件。E-R 图：椭圆属性、长方形实体、菱形联系。E-R 转关系模型：1:1 放任一端、1:N 放 N 端、M:N 必须单独成表且主键为双方联合主键。
