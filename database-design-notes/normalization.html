▸ 核心要点
1四级范式递进（层层加码）
范式要求（在前一级基础上）通俗说法
1NF字段都是不可分割的原子值表中不能"套小表"
2NF每个非主属性完全依赖候选键（消除部分依赖）不能有联合主键被"部分决定"
3NF非主属性不传递依赖其他非主属性（消除传递依赖）每列只和主键直接相关
BCNF每个决定因素都含候选键（消除主属性间的部分/传递依赖）消除 3NF 下的剩余异常

口诀："一原子、二无部分、三无传递、BC 决定因素皆含码"。

2贯穿案例：学生教务系统

初始模式：学生(学号，学生姓名，系号，系主任姓名，课程号，成绩)
依赖：学号→姓名，学号→系号，系号→系主任，(学号,课程号)→成绩

  • 不满足 2NF：候选键 (学号,课程号)，但 学号→姓名 是部分依赖。
  • → 2NF 分解：学生(学号,姓名,系号,系名,系主任) + 选课(学号,课程号,成绩)。
  • 不满足 3NF：学号→系号→系主任，存在传递依赖。
  • → 3NF 分解：学生(学号,姓名,系号) + 系(系号,系名,系主任) + 选课(学号,课程号,成绩)。
3BCNF：3NF 还不够时

仓库管理(仓库ID，存储物品ID，管理员ID，数量)，已满足 3NF，但仍有三种异常：

  • 删除异常：仓库清空后，管理员信息也被删。
  • 插入异常：仓库没物品时，无法分配管理员。
  • 更新异常：换管理员要改所有行。

→ BCNF 分解：仓库管理(仓库ID，管理员ID) + 仓库(仓库ID，存储物品ID，数量)。

⚠ 判断某关系属于第几范式：先找候选键 → 看有无部分依赖（有则仅 1NF）→ 看有无传递依赖（有则 2NF）→ 看决定因素是否都含码（否则 3NF，含码则 BCNF）。
◆ 费曼

范式就是"一张表只干一件事"的严格程度。1NF：每个格子里只能有一个值；2NF：别让"学号"这种半个主键就单独决定别的列；3NF：别让"系号"这种非主键去决定"系主任"；BCNF：更严格，连主属性之间的依赖也要拆干净。逐级拆分的目的只有一个——消除插入、删除、更新异常。

◆ 逻辑关系 — 范式递进
1NF（原子）→ 2NF（无部分依赖）→ 3NF（无传递依赖）→ BCNF（决定因素含码）
每级都是上一级的子集：BCNF ⊂ 3NF ⊂ 2NF ⊂ 1NF

▸ 总结

范式递进：1NF 原子值 → 2NF 无部分依赖 → 3NF 无传递依赖 → BCNF 决定因素皆含码。判断顺序：找候选键 → 查部分依赖 → 查传递依赖 → 查决定因素。目标是消除插入/删除/更新异常。
