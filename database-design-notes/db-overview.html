▸ 核心要点
1数据 / 数据库 / DBMS / DBS 层层递进
术语定义记忆点
数据 Data描述事物的符号记录文本/图形/图像/音频/视频
数据库 DB长期存储、有组织、可共享的大量数据集合四大特征：共享、冗余小、独立性强、易扩展
数据库管理系统 DBMS管理数据的软件，实现共享数据的组织、管理和存取功能：数据定义、操作、运行管理、存储管理、建立维护
数据库系统 DBS采用数据库技术的计算机系统四部分：数据库 + 硬件 + 软件 + 人员(DBA/程序员/用户/设计员)
2三级模式（三个抽象层次）
模式别称面向对象描述内容数量
外模式用户模式应用程序/用户用户的数据视图 View多个
概念模式模式 / 逻辑模式数据库设计人员整体逻辑结构（列标题、表联系、类型长度）一个
内模式物理模式 / 存储模式物理存储数据在磁盘如何存储（堆文件/索引/Hash）一个
⚠ 易错：概念模式、内模式只有 1 个，外模式有多个（不同用户视图不同）。视图中的数据是查询/计算出来的，基本表数据才是真正存储的。
3两级映像 → 两级数据独立性
映像体现含义典型例子
外模式 / 概念模式映像逻辑独立性改概念模式不影响外模式把"库存""销量"拆到新表，改映像仍提供原视图
概念模式 / 内模式映像物理独立性改内模式不影响概念/外模式.xls 存成 .xlsx，或加索引改存储结构

口诀："外概逻辑、概内物理" —— 靠上（外↔概）管逻辑，靠下（概↔内）管物理。

◆ 费曼

三级模式=一张 Excel 的三种视角：内模式是"另存为时选什么格式/存在哪"（物理层）；概念模式是"表格的列标题和表结构"（逻辑层）；外模式是"给不同人看哪些列"（视图）。两级映像是"翻译规则"——你改了底层存储格式，只要翻译规则不变，别人看到的表一点没变，这就是物理独立性；你改了表结构，只要调整视图的翻译，用户看到的还是老样子，这就是逻辑独立性。

◆ 逻辑关系 — 三级模式与两级映像
外模式(视图)
↑ 外模式/概念模式映像（逻辑独立性）
概念模式(逻辑结构)
↑ 概念模式/内模式映像（物理独立性）
内模式(物理存储)

▸ 总结

数据库是"数据集合"，DBMS 是"管理软件"，DBS 是"系统（库+硬件+软件+人）"。三级模式自外向内为外模式（视图）→ 概念模式（逻辑）→ 内模式（存储）；两级映像分别保证逻辑独立性（外↔概）与物理独立性（概↔内）。
