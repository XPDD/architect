▸ 核心要点
1反规范化（牺牲规范化换性能）
维度内容
益处降低连接操作需求、降低外码和索引数目、可能减少表数、提高查询效率
代价数据重复存储、浪费磁盘、可能破坏数据完整性、增加维护复杂性、降低修改速度
2反规范化 5 种方式
方式做法
增加冗余列多表保留相同列，减少连接
增加派生列增加可计算生成的列，避免计算/集合函数
重新组表把常一起查询的两表合成一张表
水平分割表按行（列值）拆到多个表；用于数据规模大、数据相对独立、多介质存储
垂直分割表按列拆（主键+部分列 / 主键+其他列），减少 I/O 次数
⚠ 区分：水平分割=按行拆（如按年份/地区），垂直分割=按列拆（如常用列与不常用列）。
3模式分解的两个判定
判定含义要点
保持函数依赖分解后各子模式保持原依赖集不变注意消除冗余依赖（如传递依赖）
无损分解分解后能还原原关系模式不能还原 = 有损

两关系模式无损判定定理：分解 p={R1,R2} 无损 ⇔ R1∩R2 → R1−R2 或 R1∩R2 → R2−R1（公共属性能决定某一方的"独有属性"）。三个及以上用表格法。

⚠ 例：U={A,B,C}，F={A→B，B→C}，分解 R1(A,B)、R2(A,C)。公共属性 A，R1−R2=B，A→B 成立 → 无损；但 B→C 在 R2 中无法保持（B 不在 R2）→ 不保持函数依赖。故"无损但不保持"。
◆ 费曼

规范化是"拆表避免异常"，反规范化是"故意合表提速"。两者方向相反：报表查询要快就多冗余；写入要一致就多拆分。模式分解两个标准——"无损"是拆了还能拼回原样（不丢数据），"保持依赖"是原约束一个都不少。理想是两者兼得，但常需取舍。

▸ 总结

反规范化用冗余换查询性能（5 方式：增冗余列/增派生列/重组表/水平分割/垂直分割）。模式分解看两点：无损分解（R1∩R2→R1−R2 或 →R2−R1）与保持函数依赖。
