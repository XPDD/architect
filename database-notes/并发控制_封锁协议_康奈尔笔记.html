▸ 核心要点
1事务 — ACID 四大特性（P54）
A
原子性 Atomicity（操作）
  • 要么全做，要么全不做
  • 银行转账：未完成前所有操作无效
C
一致性 Consistency（数据）
  • 事务发生后数据一致
  • 不会A转出B没收到的状态
I
隔离性 Isolation（执行）
  • 事务间互相隔离互不干涉
  • 未提交的更新不可见
D
持续性 Durability（改变）
  • 事务结果持续保存
  • 一旦提交，永远有效

事务以 第一个 DML 操作 开始，以 rollback、commit 或 DDL 语句 结束。事务是并发控制的前提条件。

2并发控制 — 三大问题（P54-P55）
问题场景白话理解
丢失更新 T1修改A并写回 → T2也修改A并写回 → T2覆盖T1 两个人同时改同一格，后写的覆盖先写的，第一个人的修改白做了
不可重复读 T2读A → T1修改A并写回 → T2再读A发现变了 前后两次读同一格，数据不一样（被中间改掉了）
读脏数据 T1修改A → T2读A → T1回滚 → T2读到的数据无效 读了别人还没确认的草稿，结果人家撤销了，读到假数据
3封锁协议 — X锁 / S锁 + 三级协议（P56-P58）

两种锁

X
X 锁 — 排它锁（写锁）
  • 加锁事务：可读可写
  • 其他事务：不能加任何锁
  • 释放后才允许别人加
S
S 锁 — 共享锁（读锁）
  • 加锁事务：只能读不能改
  • 其他事务：只能加 S 锁（可读不可改）
  • 释放后才可加 X 锁

三级封锁协议

① 一级封锁协议
  • 修改前加 X 锁
  • 事务结束才释放
✓ 丢失更新
✗ 不可重复读
✗ 读脏数据
② 二级封锁协议
  • 一级基础上：
    读前加 S 锁，读完释放
✓ 丢失更新
✗ 不可重复读
✓ 读脏数据
③ 三级封锁协议
  • 一级基础上：
    读前加 S 锁，事务结束释放
✓ 丢失更新
✓ 不可重复读
✓ 读脏数据

关键区别 — 二级 vs 三级

  • 二级：S锁读完即释放 → 读完后可能被改 → 不解决不可重复读
  • 三级：S锁事务结束才释放 → 整个事务期间锁住 → 三个全解决

答案：A. 可读不可写

◆ 费曼

事务ACID就是"银行转账四承诺"：原子性=要么全转要么一分不动（不能转一半），一致性=A扣了B一定到账（不会凭空消失），隔离性=别人不能看到你转账到一半的过程（隐私），持续性=转完钱不会因为停电消失（永久生效）。并发三大问题想象几个人同时编辑同一个Excel：丢失更新=你改完不保存，同事覆盖了你的修改；不可重复读=你看了一下数据，同事中间改掉了，你再看时已经变了；读脏数据=同事改了一格还没保存就撤销了，你在这中间看了个假数字。三级封锁协议就像图书馆规则：一级=借走书才锁（写锁），二级=借走+阅览都锁但看完就解锁（别人可以插进来改），三级=阅览也锁到整个事务结束（最高级别，全保护）。

▸ 总结

事务ACID（原子性/一致性/隔离性/持续性）是并发控制前提。并发不控制会引发丢失更新（覆盖）、不可重复读（前后不一致）、读脏数据（读到未提交回滚数据）三大问题。X锁只我改、S锁大家读。一级→二级→三级逐级增强：一级消丢失更新、二级加消读脏数据、三级全消。二级vs三级关键：S锁释放时机（读完/事务结束）。
