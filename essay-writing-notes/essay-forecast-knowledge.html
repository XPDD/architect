▸ 核心要点
1论题一：云原生微服务架构与服务治理

预测逻辑：2025年5月考事件驱动、11月考 Serverless，微服务本体+治理技术是自然延伸；服务网格、可观测性尚未独立命题。

技术域代表产品核心作用 / 论文写法要点 服务拆分DDD 领域驱动按业务领域边界拆，单一职责；论文可写"将系统按用户/订单/支付域拆分" 注册发现Eureka / Nacos服务启动注册、消费者按服务名查 IP/端口、心跳健康检查 配置中心Apollo / Nacos动态配置、免发版切换（日志开关/限流阈值） API 网关Spring Cloud Gateway / Kong统一入口、路由、鉴权、限流 服务治理熔断/降级/限流/负载均衡雪崩防护核心，论文最亮的技术点 可观测性SkyWalking/Jaeger · Prometheus · ELK/Loki链路追踪+指标监控+日志聚合三件套 服务网格Envoy Sidecar · Istio · mTLS流量管理、零信任安全，尚未独立命题 容器化Docker + K8sDeployment/Service/Ingress/HPA 自动扩缩容
①
熔断 vs 降级 vs 限流
  • 熔断：依赖服务故障时快速失败返回备选，防止雪崩（如 Hystrix/Sentinel 断路器）
  • 降级：主动牺牲非核心功能保核心（如双11关推荐、返回兜底数据）
  • 限流：控制进入流量速率，防压垮（令牌桶/漏桶）
  • 口诀：熔断"别人坏了我不等"，降级"我主动砍功能"，限流"进门限量"
②
论文三问写法建议
  • 分论点1：服务拆分（DDD）→ 解耦问题
  • 分论点2：注册/配置/网关治理 → 管理难问题
  • 分论点3：熔断降级限流 + 可观测性 → 雪崩问题
  • 进阶加分：Istio 服务网格流量管理 + mTLS 零信任
2论题二：数据库架构与多模数据架构

预测逻辑：数据架构每年必考；向量数据库作为 AI 时代新存储，与传统关系/图/文档库构成多模统一。

数据库类型代表产品典型场景论文中怎么写 云原生关系库TiDB / PolarDB / OceanBase交易、ERP、核心账务存储-计算分离、HTAP、水平扩展 图数据库Neo4j / TuGraph风控、社交关系、知识图谱多跳关系查询、路径分析 向量数据库Milvus / Weaviate / PGVectorRAG、推荐、相似度检索embeddings 存储、ANN 近邻检索 实时采集Kafka / Pulsar、CDC 技术异构数据实时同步Binlog/CDC 捕获、消息队列缓冲 流处理引擎Flink窗口计算、实时指标Checkpoint 状态管理、Exactly-Once 实时 OLAPClickHouse / Doris实时分析列式存储、预聚合物化视图

多模架构 = "一库多型 + 实时链路"

  • 一个业务系统按数据特征选多类库：交易用关系库、风控用图库、AI 检索用向量库
  • 实时链路：业务库 → CDC/Kafka → Flink 流处理 → ClickHouse/Doris OLAP
  • 论文三问建议：分论点1 多模选型与理由（为什么各场景选各库）；分论点2 实时采集与流处理链路；分论点3 一致性/性能落地难点与效果

①
令牌桶 vs 漏桶
  • 令牌桶：匀速放令牌，桶内可存，允许突发流量（限平均速率+容忍突发）
  • 漏桶：匀速流出，桶满丢弃，强制平峰（无突发）
  • 高并发场景一般选令牌桶，兼顾突发与平滑
②
论文三问写法建议
  • 分论点1：瓶颈分析（火焰图定位 CPU/慢查询定位 DB）
  • 分论点2：多级缓存 + 异步化削峰（缓存一致性：Cache Aside/双删）
  • 分论点3：韧性（熔断限流舱壁）+ 容量（压测/伸缩/混沌）
  • 结尾量化：TP99 从 500ms→100ms、QPS 1000→5000
4论题四：论 AIGC 技术对软件架构设计的影响与应用

预测逻辑：论文必考未来技术；2025年5月已考 AI 测试方向，下半年可能考大模型或具体应用技术。

①
研发提效方向
  • 设计文档辅助生成（需求→架构文档初稿）
  • 技术方案辅助评审（AI 检查方案漏洞/对比）
  • AI 编程助手对开发流程、架构模式的影响
②
智能运维方向
  • 基于大模型的智能编程助手
  • 基于大模型的系统运维助手（日志分析/故障定位）
  • AI 能力如何嵌入现有架构（网关+LLM 服务+向量库）

论文写法要点

  • 架构上：引入 LLM 网关 + Prompt 编排 + 向量库 RAG + 私有化部署，作为"AI 中间层"
  • 分论点建议：1 需求文档生成提效；2 代码生成与评审的流程改造；3 AI 运维助手落地
  • 注意：AI 题凭能力选，一般不建议选；选了必须有真实落地细节
5论点寻找方式（通用方法论）

核心心法：从题目出论点，不是凭空想

  • 三问联动：子问题3一般划分 3 个点；若题目第三问没给定论点，就把第二问的解答方向当作第三问的总论点（总分原则）
  • 回应子题目：正文必须逐条回应论文子题目，论点从子题目的问法里"抠"出来
  • 作业法：把近6年不超纲的论文题目，每个都写出 3 个论点，再挑 3 个主题重点记忆（直播上 P30 作业）
①
从"技术栈清单"切分
  • 看考察点清单，按技术域切成 3 段 = 3 个分论点
  • 例（微服务）：拆分 → 治理 → 熔断可观测
  • 例（多模）：选型 → 实时链路 → 落地效果
  • 每个分论点内部：论点解释 → 项目问题 → 方案取舍 → 技术 → 结果
②
从"项目真实经历"切分
  • 复盘项目：当时遇到了哪 3 个大坑/大决策 → 就是 3 个论点
  • 每个论点必须有真实技术细节支撑（为什么选它+对比了什么）
  • 论点清晰且有思路时，正文不写无关废话（范文3点评）
  • 落笔顺序：论点 → 结合项目 → 问题 → 方案取舍 → 结果

◆ 费曼

四大预测论题 = 四个"万能项目场景"。 微服务治理讲的是"拆开之后怎么管"（注册/配置/网关+熔断限流+可观测），多模数据库讲的是"数据各有归宿 + 实时流动"，性能优化讲的是"瓶颈→缓存→异步→韧性→容量"一条龙，AIGC 讲的是"把大模型变成系统里的新能力层"。备考动作：每个论题挑一个真实项目，按上面的"三问分论点"结构各写一篇，核心是让每个技术点都有"为什么选它 + 对比了什么 + 量化效果"。

▸ 总结

四大预测论题知识点：微服务治理=DDD拆分+注册/配置/网关+Nacos/网关+熔断/降级/限流/负载均衡+可观测性+服务网格+K8s；多模数据库=关系(TiDB)/图(Neo4j)/向量(Milvus)各配场景 + CDC/Kafka→Flink→OLAP 实时链路；性能优化=瓶颈分析→多级缓存→异步化→韧性(令牌桶/漏桶/Sentinel)→容量保障；AIGC=文档生成+方案评审+AI编程+智能运维四方向。每个论题按"三问分论点"写，技术点务必配"为什么+对比+量化效果"。
