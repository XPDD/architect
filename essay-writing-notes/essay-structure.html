▸ 核心要点
1论文六段式结构（全文骨架）

整体脉络：摘要 → 背景 → 三子问题 → 结尾

  • 摘要：全文浓缩，先声夺人 —— 阅卷官最先看这里
  • 背景：350-450字，只跟项目有关，可适配任何题目
  • 第一子问题：时间+项目+岗位+职责+投入+历时+好评 + 功能模块 + 技术
  • 第二子问题：结合上下文综合回答，不单独列问题；总分原则在此埋伏笔
  • 第三子问题：划 3 点分段回答，先解释论点 → 再结合项目
  • 结尾：上线效果（量化）+ 客户评价 + 收获 + （不足和解决思路）

2摘要：六要素一网打尽
  • 时间 + 项目简介 + 个人岗位 + 工作职责 + 投入 + 历时 + 成功交付客户好评
  • 最后一句：结合具体题目，说明本文结构（"下面将从 XX、XX、XX 三方面论述"）
  • 口诀：时项岗职投历好 + 结构
3背景：只写项目，可适配一切题目

项目背景 + 过渡部分

  • 建议 350-450 字，只跟项目有关，不涉及题目具体论点
  • 写清：行业痛点 → 为什么立项 → 项目目标/规模 → 你的角色
  • 价值：同一段背景 可套用到任何论文题目，考前背熟即可
4三个子问题：层层递进的论证逻辑

子问题 1 — 项目总体介绍

  • 时间+项目简介+岗位+职责+投入+历时+好评（不要整段抄袭摘要）
  • 简要介绍几个功能模块 + 项目所用技术
  • 注意：看题目第一问有没有额外的具体要求

子问题 2 — 综合回答 + 埋伏笔（总分原则）

  • 结合上下文和项目综合回答，不要单独把问题列出来答
  • 关键技巧：若第三问没给定论点，就把第二问的解答方向作为第三问论点 —— 这就是"总分原则"
  • 让文章整体形成"总论点 → 分论点"的闭环

子问题 3 — 划 3 点，分段论证（得分重头）

  • 一般来说第三个子问题都划分为 3 个点并分段回答
  • 每点套路：先解释论点 → 再记叙项目与该论点的关联 → 项目之前的问题 → 你做的方案 → 方案取舍 → 为什么选它 → 涉及哪些技术 → 结果如何
  • 注意：这里不要写项目采用方案后的不足，放在结尾写
5结尾：字数策略决定要不要写不足

必写项 + 弹性项

  • 必写：项目上线及运行效果（用可量化的数据）+ 客户评价 + 项目收获
  • 弹性：项目不足和解决思路 —— 看字数
  • 前面已 2000 字 → 可不写不足；字数不够 → 必须写不足+解决思路，水 2、300 字
◆ 费曼

论文=一套"总分总"的证明题。 摘要是把结论先亮出来（我是谁、做了什么、成功了）；背景是铺垫舞台（项目为什么值得做）；三个子问题就是论证主体——第一问介绍"舞台布景"（项目本身），第二问开始切入主题论点，第三问把论点拆成 3 个分论点逐个用"问题→方案→取舍→结果"证明；结尾再回到"总分"给出成绩单（量化效果+客户好评）。记住：第三问的 3 个分论点，就是你的得分点，每点必须落到项目真实技术和方案取舍上，不能空谈概念。

▸ 总结

论文六段式 = 摘要（六要素+结构）→ 背景（350-450字项目铺垫）→ 子问题1（项目+模块+技术）→ 子问题2（综合回答并埋伏"总分"论点）→ 子问题3（3点分段论证，论点→问题→方案→取舍→技术→结果）→ 结尾（量化效果+客户评价+收获，字数不够再补不足）；核心心法=总分原则让全文一个论点贯穿，三子问题用真实项目技术说话。
