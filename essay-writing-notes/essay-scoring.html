▸ 核心要点
1评分标准全景：六段结构 = 六处采分点
段落核心要求采分点 1. 摘要浓缩全文 + 说明结构时项岗职投历好 + 结合题目说明结构 2. 背景项目铺垫，350-450字只跟项目有关，可适配任何题目 3. 子问题1项目总体介绍项目+岗位+职责+投入+历时+好评+模块+技术 4. 子问题2综合回答 + 埋伏笔不单独列题回答；方向作为子3论点（总分原则） 5. 子问题3划 3 点分段论证论点→项目关联→问题→方案取舍→技术→结果 6. 结尾效果 + 评价 + 收获（+不足）量化效果 + 客户评价 + 收获；字数够可省不足
21. 摘要：六要素 + 结构句
  • 时间 + 项目简介 + 个人岗位 + 工作职责 + 投入 + 历时 + 成功交付客户好评
  • 最后一句：结合具体题目说明本文结构
  • 口诀：时项岗职投历好 + 结构
32. 背景：350-450 字，可复用
  • 项目背景 + 过渡部分，建议 350-450 字
  • 只跟项目有关，可以适配任何论文题目
  • 价值：考前背熟 → 考场上直接默写
43. 第一子问题：项目介绍（勿抄摘要）
  • 时间+项目简介+岗位+职责+投入+历时+成功交付客户好评
  • 简要介绍几个项目功能模块 + 项目所用技术
  • 注意：不要对着摘要全部抄袭；看第一问有没有额外问题需要回答
54. 第二子问题：综合回答 + 总分原则
  • 结合上下文综合你的项目来回答，不要单独把问题列出来回答
  • 看题目有没有在第三问给定论点；如果没有，就把第二问解答方向作为第三问的论点
  • 效果：文章符合"总分"原则（总论点 → 分论点闭环）
65. 第三子问题：划 3 点分段论证（得分重头）

一般划分为 3 个点，分段回答

  • 每点套路：先针对论点解释 → 记叙项目与该论点有关联的地方 → 项目之前存在的问题 → 你做了哪些方案 → 方案如何取舍 → 选择了哪一个 → 涉及哪些技术 → 最后结果如何
  • 注意：这里不要说你项目采用这些方案之后的不足，放在结尾写
76. 结尾：量化效果 + 字数策略

必写 + 弹性

  • 必写：项目上线及运行效果（用可量化的数据）+ 客户评价 + 项目收获
  • 弹性：不足和解决思路 —— 看字数
  • 前面已 2000 字 → 不写不足也可以
  • 字数不够 → 必须写不足和解决思路，水 2、300 字
8这个标准怎么用？（鉴赏范文 / 自查）
①
鉴赏范文
  • 拿六段逐段打分：摘要要素齐吗？背景通用吗？子2埋伏笔了吗？
  • 对照范文4（架构风格）：每段"先特点后项目"就是子3的完美示范
  • 对照范文7（云原生）：通篇没讲云原生 → 子问题没回应题眼
②
自查自己的论文
  • 写完逐段核：摘要六要素 / 背景字数 / 子1没抄摘要
  • 子2是否立了总论点、子3是否3点都"论点→问题→方案→技术→结果"
  • 结尾量化数据在不在、字数够不够要不要补不足
◆ 费曼

评分标准 = 阅卷官的"打分清单"，反过来就是你的"写作检查表"。 六段每段都有明确的采分点：摘要看六要素齐不齐、背景看能不能套用、子1看有没有抄摘要、子2看有没有"总分"埋伏笔、子3看是不是3点且每点"论点→问题→方案→技术→结果"、结尾看有没有量化数据和字数策略。写完后拿这份清单逐段自查，就能把分数一处处"捡"回来；鉴赏范文时也用同一把尺子量——范文4满分示范、范文2/6/7各有失分点，都逃不过这六条。

▸ 总结

论文鉴赏评分标准 = 六段六采分点：摘要（时项岗职投历好+结构）、背景（350-450字只写项目可适配一切题目）、子问题1（项目+模块+技术、勿抄摘要）、子问题2（综合回答并立总分论点）、子问题3（划3点，每点"论点→项目→问题→方案取舍→技术→结果"，不足留到结尾）、结尾（量化效果+客户评价+收获，字数不够必须补不足水2-300字）；既是阅卷清单也是写作自查表，鉴赏范文用同一把尺子。
