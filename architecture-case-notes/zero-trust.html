▸ 核心要点
1先把题目翻译成大白话

银行 App 有四个"入口区"：私有云、分支行网点、外包接口、员工远程办公。安全团队发现四类风险：员工账号被钓鱼后能潜入内网乱窜、App 接口被刷、外包接口没验证还能改数据、内网运维口子开得太大。

传统做法是"砌一堵墙"把内网护起来，但墙内一旦被攻破就"如入无人之境"。于是改用零信任：不再因为"你在内网"就信任你，每次访问都要查身份、查设备、查上下文。

2名词速查（不懂的词看这里）
传统边界防御"城堡+护城河"模型：用防火墙/VPN 围一圈，墙外不可信、墙内默认可信
边界 / DMZ内网与外网之间的隔离区；DMZ 放对外服务的缓冲地带
横向移动攻击者攻破一个点后，在内网里"从一台机器跳到另一台"
零信任不区分内外网，默认不信任，每次访问都持续验证（Never Trust, Always Verify）
最小权限只给完成任务所需的最小权限，按需授权、动态收敛
微隔离把内网按业务/身份再切成很多小格子，控制东西向流量，防横向移动
持续信任评估结合设备指纹、行为、地理位置等动态打分，随时调整信任
多因素认证 MFA口令 + 短信/OTP/生物识别，多一道验证
IAM / SSO统一身份管理与单点登录
API 网关所有接口的统一入口，做鉴权、限流、审计
防重放用"时间戳 + 随机数"防止别人把旧请求重发一遍
国密 SM2/SM3/SM4国产密码算法：SM2 非对称(签名/验签)、SM3 摘要(完整性)、SM4 对称(加密)
密评 / 等保 2.0商用密码应用安全性评估 / 等级保护，合规要求
3传统边界防御是什么？为什么它不管用了？

是什么（城堡模型）：传统安全像一座城堡——在内外网之间砌一道墙（防火墙、VPN、WAF、DMZ），墙外（互联网）不可信、墙内（内网）默认可信。只要校验通过进了内网，就当成"自己人"，可以相对自由地访问内部资源。

为什么失效：

  • 边界模糊了：云、移动办公、外包、SaaS、员工自带设备（BYOD），"内网"已经没有了清晰的一道墙。
  • 墙破一次就全完：钓鱼、弱口令、VPN 漏洞一旦突破边界，攻击者在内网可横向移动（东西向流量）。
  • 内网太"扁平"：内部无隔离，一台机器沦陷就能摸到核心系统。
  • 只信"位置"不信"人"：默认"在内网=可信"，忽略了账号是否被盗、设备是否安全。
◆ 传统边界防御（城堡模型）
互联网（不可信）
↓ 穿过一道"墙"
防火墙 / VPN / WAF / DMZ（边界）
↓ 进去就"默认可信"
内网（扁平 · 可自由横向移动）= 一旦破墙，如入无人之境
4零信任的三大核心原则
  1. 永不信任、持续验证：每一次访问都先验证身份 + 设备 + 上下文，不因为"在内网"就放行；而且不是一次验证就永久信任，而是持续评估。
  2. 最小权限：只给完成当前任务所需的最小权限，按需授权、动态收敛，权限随上下文变化（并可设时间限制）。
  3. 微隔离：把内网按业务与身份进一步切成许多小隔离区，精细化控制东西向流量，把横向移动的路堵死。

一句话：默认拒绝（Default Deny），以"身份 + 设备 + 上下文"为信任依据，构建以身份为中心的动态访问控制。

◆ 零信任：每次访问都"查证件 + 看情况"
访问请求（无论来自内外网）
↓ 默认不信任
验证身份（MFA/SSO）
＋
校验设备安全
＋
评估上下文/风险
↓ 通过则授予"最小权限"，否则拒绝；并持续再评估
微隔离：只放行到该资源的最小通路
5本质差异：传统边界防御 vs 零信任（题目重点）
传统边界防御
  • 信任依据：网络位置（在内网=可信）
  • 策略：一次通过边界、进入即信任
  • 防护重点：南北向（内外网边界的防入侵）
  • 内网：扁平，可横向移动
  • 风险：破墙一次，全盘皆输
VS
零信任
  • 信任依据：身份 + 设备 + 上下文（与位置无关）
  • 策略：默认拒绝、每次访问都验证、持续评估
  • 防护重点：东西向（内网横向移动）
  • 内网：微隔离，最小通路
  • 收益：单点失陷不扩散
维度传统边界防御零信任
信任模型内网可信、外网不可信（边界内=默认信任）任何位置都不可信，默认拒绝、持续验证
信任依据网络位置（IP / 网络区域）身份 + 设备 + 上下文（动态风险）
访问控制粗粒度、基于网段细粒度、基于身份、最小权限
横向移动内网扁平，易横向渗透微隔离，东西向受控
典型技术防火墙、VPN、DMZ、IDS/IPSIAM/SSO、MFA、微隔离、持续评估、API 网关

最本质的一句话：传统边界防御是"进了院门就是自己人"；零信任是"每一次进屋都要重新查证件、看状态"——从"信任网络位置"转向"信任身份与上下文"。

6落地：员工账号被钓鱼后怎么防横向渗透（问题 2）
层面措施
身份认证多因素认证（口令 + 短信/OTP/生物识别）；统一身份与单点登录（IAM / SSO）
持续信任评估结合设备指纹、行为画像、地理位置、异常行为（异地登录、异常时点）做动态风险评分，高风险降权或强制二次认证
访问控制基于角色的最小权限 + 动态访问策略（按项目/资源细分）；敏感系统"按需申请、审批 + 时长限制"
7落地：API 安全防护（问题 3：App 接口 + 外包接口）
接口防护措施
App 接口OAuth2 / JWT 鉴权；设备指纹绑定；接口加密（国密 SM4）；提交频率风控限流 + 设备风控（黑名单、指纹识别）
外包接口由 API 网关统一接入；为外包方签发应用凭证（AppKey/密钥）；请求加时间戳 + 随机数 + 签名（SM3 摘要 + SM2 验签）防篡改与防重放；调用额度与频率限制、日志审计留痕

防重放要点：请求里带时间戳（超出时间窗即拒）+ 随机数 nonce（用过即失效），再叠签名，攻击者截获旧报文也无法重放。

8落地：国密算法用途 + 密评/等保约束（问题 4）
算法类型本方案用途
SM4对称加密业务敏感数据与链路的加密（App 与服务器间传输、数据库敏感列）
SM3摘要 / 哈希消息完整性校验、签名摘要、防篡改
SM2非对称数字签名验签、证书体系、通信身份认证（双向认证）

合规约束：密钥管理要符合国密要求（密钥托管）；按等级保护与商用密码测评（密评）要求，重要系统须通过密评；加密算法、密钥管理、审计留存要符合监管口径，架构设计须预留国密改造与合规证明材料。

记忆：SM2=签名（非对称，一对密钥）、SM3=摘要（完整性，单向）、SM4=加密（对称，一把密钥）。

9回到题目四小问（要点速记）
问题要点
问题1三大原则＝永不信任持续验证/最小权限/微隔离；本质差异＝传统"内网可信、按位置信任、重边界"，零信任"默认拒绝、按身份+设备+上下文持续验证、重东西向微隔离"
问题2身份认证（MFA/SSO）+ 持续信任评估（设备/行为/地理动态评分）+ 访问控制（最小权限、按需审批、时长限制）
问题3App：OAuth2/JWT + 设备指纹 + SM4 加密 + 风控限流；外包：API 网关 + AppKey + 时间戳/随机数/签名（SM3+SM2）防篡改防重放 + 额度限流 + 审计
问题4SM4 加密、SM3 摘要、SM2 签名；密钥托管；通过密评、满足等保 2.0，预留合规材料
◆ 费曼

零信任说人话：老办法像"小区大门口保安"——进了大门就随便逛，谁要是混进来（钓鱼盗号），就能在小区里到处撬门（横向移动）。零信任改成"每进一栋楼、每个房间都要刷卡查身份"：你是谁（身份）、你的卡是不是本人（设备）、现在这个时间地点正不正常（上下文），都对了才放行，而且只开到你要去的那扇门（最小权限），楼与楼之间还隔开（微隔离）。所以本质差异就一句——老办法信"你站在院内"，零信任信"你是谁 + 设备状态 + 上下文"，默认谁都不信、每次都要验。

▸ 总结

传统边界防御＝城堡模型（防火墙/VPN 围一圈，内网默认可信、重南北向边界、内网扁平易横向移动）；零信任＝永不信任、持续验证，以身份+设备+上下文为信任依据、默认拒绝。三大原则＝永不信任持续验证 / 最小权限 / 微隔离；本质差异＝从"信任网络位置"转向"信任身份与上下文"、从南北向转向东西向微隔离。落地：MFA/SSO + 持续信任评估 + 最小权限；API 用 AppKey+时间戳+随机数+签名防篡改防重放；国密 SM4 加密 / SM3 摘要 / SM2 签名，满足密评与等保 2.0。
