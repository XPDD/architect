▸ 核心要点
1数据库 · 考试特点
  • 一定会给一个数据库选型或应用场景（关系型 / 内存型 / NoSQL）。
  • 必考 NoSQL，其中被考概率最高的就是 Redis（缓存三剑客、分布式锁、持久化）。
  • 趋势是至少一问「操作类选择题」，没用过基本答不上，拿 7–10 分容易、高分靠经验。
  • 若题目带比较表格（选型对比），建议优先选它，基本能拿 10 分以上。
2缓存一致性 · 实时 vs 异步更新
实时同步更新
  • 每次数据更新时，立即同步更新缓存和数据库，确保两者一致
  • 保证缓存数据始终最新，适合一致性要求高的场景
  • 但性能开销大，写路径变长
⇄
异步准实时更新
  • 数据库更新后，稍后通过异步机制更新缓存
  • 通过批量/定时同步，数据在一定时间内趋于一致
  • 适合读多写少、对响应速度要求极高的场景

真题选型：仓储管理系统「反馈起运地+送达时间、响应<1 秒」应选异步准实时更新——因为读操作远多于写操作、对响应速度要求极高，异步能减少实时同步性能开销、保证高效与体验。

3哈希 vs 一致性哈希
哈希算法
  • 键值经哈希函数生成固定长度哈希值，映射到不同缓存节点
  • 节点扩展/减少时，需重新分配大量数据，易「缓存抖动」
⇄
一致性哈希
  • 节点和数据映射到虚拟环形空间，按哈希值找最近节点存储
  • 增/减节点时仅一小部分数据需重分配，扩展性稳定性更好

选型：扩容场景应选一致性哈希——节点变化时只需重分配少量数据，有效避免传统哈希的「缓存抖动」问题，提高稳定性与扩展性。

4布隆过滤器 · 原理与优缺点

布隆过滤器是空间效率高的概率型数据结构，用多个哈希函数把数据映射到一个位数组。判断存在时检查多个哈希值对应位是否全为 1：有任一为 0 → 一定不存在；全为 1 → 可能存在（可能误判）。

  • 优点：占用内存小、查询速度快，适合大规模数据。
  • 缺点：有假阳性（可能误判不存在的数据为存在），无法删除已添加的数据。
  • 应用：提前过滤无效/非法查询请求，解决缓存穿透。穿透＝查询根本不存在的数据（如恶意请求不存在 ID），缓存永不命中、每次都打数据库。
  • 缓存击穿：某个热点 key 过期的瞬间，大量并发请求同时打到数据库，用互斥锁 / 逻辑过期解决；缓存雪崩：大量 key 同时失效或 Redis 宕机，用随机 TTL / 多级缓存 / 集群解决。（三者区分！）
5分布式锁 · MySQL 实现的缺点
1
性能瓶颈
  • 高并发下大量锁请求/释放使数据库性能下降
    • 2
    单点故障
  • MySQL 单点，数据库故障则整个分布式锁失效
    • 3
    锁粒度问题
  • 粒度过大降低并发性能，过小增加锁冲突概率
    • 4
    数据一致性
  • 多节点数据同步延迟/不一致影响锁有效性
    • 5
    扩展性差
  • 单库难以满足性能容量需求，扩展复杂成本高
    • 6
    容错性差
  • 不如 ZooKeeper / Redis 方案，网络分区时不可靠

    • Redis 分布式锁死锁场景：客户端 A 获锁后执行任务，但执行时间超过锁有效期，锁自动过期释放；客户端 B 获锁。此时 A 尚未完成任务仍以为自己持锁继续执行，导致多个客户端对资源并发操作混乱（即多客户端互斥失效）。ZSet 相关命令：存入分数 ZADD、获取分数范围 ZRANGE、获取分数 ZSCORE。

    6cache-aside（旁路缓存）架构
    ◆ 读取数据流程
    ① 读请求 → 查询缓存是否有目标数据
    ↓
    ② 命中 → 返回商品信息
    ↓ 未命中
    ③ 访问数据库查询该商品信息
    ↓
    ④ 将查询到的数据更新到缓存
    ↓
    ⑤ 返回目标数据

    写入流程：① 更新数据库中的目标信息 → ② 将更新后的数据写入缓存（确保数据一致性）。

    多线程一致性问题：读写线程并发导致缓存与数据库不一致（如写线程未更新完缓存时，读线程读到旧数据）。解决办法：① 加锁同步（对缓存操作加互斥锁，读写互斥）；② 设置缓存过期时间（强制刷新，缩小不一致窗口）；③ 延迟双删（写库后延迟再删缓存，防旧数据残留）；④ 异步队列（把缓存更新串行化，避免并发冲突）。

    ◆ 费曼

    数据库说人话：数据库题几乎必考 Redis。缓存一致性：读多写少就缓存准实时异步更新，省性能。分片：一致性哈希扩节点只挪一小部分数据，比普通哈希好。布隆过滤器：用位图判断「在不在」，省内存但有假阳性、删不了。分布式锁：别用 MySQL 做锁（单点、性能差、扩展差），Redis/ZK 更靠谱；锁快过期了 A 还在干活就是死锁场景。cache-aside 就是「先读缓存→没命中读库→回填缓存」；写一致问题用「加锁/设过期/延迟双删/异步队列」四招。

    ▸ 总结

    数据库选做题高频：缓存一致性（实时同步 vs 异步准实时，读多写少用异步）；一致性哈希（扩容只挪少量数据、防抖动）；布隆过滤器（多哈希+位数组，省内存、有假阳性、不可删）；MySQL 分布式锁六大缺点 + Redis 死锁场景 + ZSet 命令（ZADD/ZRANGE/ZSCORE）；cache-aside 读写流程与四招解决一致性（加锁/设过期/延迟双删/异步队列）。Redis 是必考核心。
