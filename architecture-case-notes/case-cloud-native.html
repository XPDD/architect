试题二
阅读以下关于某旅行公司云原生改造的说明，回答问题 1 至问题 3。
P2 · 云原生架构
【说明】

某旅行公司主体由两家公司合并后出现两个问题：技术体系不同需整合为一体，以及节假日高并发流量。公司分三阶段推进云原生改造：

  • 第一阶段：为提升集群资源利用率、降低使用成本，用云原生思维重构部分技术体系，将多套旧有系统合并、收拢到以云原生应用为核心的私有云平台，并把 IDC、物理网络、虚拟网络、计算资源、存储资源经 IaaS / PaaS 虚拟化封装、切割、再投产后实现自动化。
  • 第二阶段：随着集群规模扩大、部分机器频繁故障，保障服务稳定性成为首要任务；基于公有云、私有云、离线专属云等动态计算环境，用声明式 API、不可变基础设施、服务网格、容器服务构建容错性好、易管理易观察的应用。
  • 第三阶段：通过基础组件、服务云原生改造与服务依赖梳理，使应用不再关心底层资源/机房/运行时间/供应商；利用标准云原生应用模型实现跨地域、跨云自动化灾备、自动部署，并向云原生场景下的 DevOps 演进。

问题 1该改造分三阶段进行，请分别说明各阶段的主要目标，并指出第二阶段的首要任务。8 分

该公司合并后有「技术体系各异」与「高并发流量」两大挑战，分三阶段落地。请按阶段概括目标，并明确第二阶段的首要任务是什么、采用了哪些技术来支撑。

参考答案
  • 第一阶段：提升集群资源利用率、降低资源使用成本；将多套旧有系统合并到以云原生应用为核心的私有云平台，用 IaaS / PaaS 自动化封装调度。
  • 第二阶段：保障服务稳定性（集群规模扩大、部分机器频繁故障）；用声明式 API、不可变基础设施、服务网格、容器服务构建弹性、可观测、容错好的应用。
  • 第三阶段：实现跨地域 / 跨云自动化灾备、自动部署，使应用与底层资源完全解耦，并向云原生 DevOps 演进。
问题 2结合 8 层架构图，说明「机器资源池、基础资源层、基础平台层」的作用，并指出体现容器编排的层次。8 分

图中给出了云原生平台自下而上的 8 层。请分别说明机器资源池、基础资源层、基础平台层所承担的功能，并指出容器编排（Kubernetes）主要发生在哪一层，为什么这一层是「技术底座」。

参考答案
  • 机器资源池：提供物理机、虚拟机、混合云机器等基础硬件资源，是整个架构的硬件基石。
  • 基础资源层：封装计算（CPU/GPU）、容器网络、存储、运行时（Docker/Kata 等），向上提供「计算 / 网络 / 存储 / 容器运行」能力。
  • 基础平台层：依托 Kubernetes（容器编排）与机器学习平台提供云原生编排、AI / 大数据支撑，是业务「技术底座」。
  • 容器编排还体现在资源管理层——它统一管理 KVM（虚拟化）、Docker（容器）、Kubernetes（编排），简化虚拟机与容器的生命周期调度。
问题 3结合云原生内涵，说明为何采用「声明式 API + 服务网格 + 混合云」能同时支撑弹性与稳定性。9 分

为了应对节假日高并发与机器故障，公司引入混合云环境、容器云平台、声明式 API、服务网格。请结合云原生「最大化剥离非业务代码」的内涵与7 原则（服务化 / 弹性 / 可观测 / 韧性 / 自动化 / 零信任 / 持续演进）说明理由。

参考答案
  • 声明式 API：把期望状态交给平台，平台自动收敛到该状态，配合自动修复与弹性伸缩，体现自动化、弹性，降低人工干预故障风险。
  • 服务网格（Service Mesh）：把连接、安全、流量控制、可观测下沉为平台基础设施，与业务解耦，体现服务化、微服务化；在控制平面统一配置限流、熔断、灰度，提升韧性与可观测。
  • 混合云环境：公有云 + 私有云 + 离线专属云互补——上量时弹性扩容（弹性）、高峰期分散流量（韧性），敏感数据留私有云（零信任 / 安全），是应对节假日高并发的关键。
  • 整体符合云原生「把非功能特性交给云、专注业务代码」的内涵，进而支撑第三阶段的 DevOps 与跨云灾备。
