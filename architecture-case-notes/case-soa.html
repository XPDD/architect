试题三
阅读以下关于某企业以 SOA 整合异构系统的描述，回答问题 1 至问题 3。
P3 · SOA
【说明】

某大型企业在多年信息化建设中形成了订单、库存、会员、物流等多套业务系统，彼此技术栈异构（Java / .NET / 遗留 COBOL）、数据分散、接口千差万别，难以协作。企业希望在不推倒重建的前提下，让这些系统有序互通、服务可复用，逐步具备面向服务的治理能力。技术团队经论证决定采用面向服务架构（SOA）。

  • 通过中间件在异构环境间建立通信与转换，服务以消息 / 事件驱动方式交互，统一消息经中心化中转后分发。
  • 所有对外功能以「服务」发布：无状态接口、唯一实例、明确定义且长期稳定的接口、自包含模块化、粗粒度。
  • 建立服务注册表，支持服务的注册公布、查询定位与绑定调用。
问题 1说明 SOA 如何实现异构系统互通，指出其「总线」机制承担的作用。8 分

SOA 通过中心化中间件让异构服务以消息 / 事件驱动交互。请说明该「总线」（ESB）的作用，并指出 UDDI、WSDL、SOAP、REST 四者在 SOA 中各扮演什么角色。

参考答案
  • 企业服务总线（ESB）：面向服务的中间件技术，实现异构环境服务的消息 / 事件驱动交互，统一转换协议、处理路由，具备服务质量与可管理性，是 SOA 的连接核心。
  • UDDI：服务注册与发现——提供者公布服务、请求者查找符合要求的服务。
  • WSDL：服务描述接口（「说明书」），以 XML 描述服务提供的操作与输入输出。
  • SOAP：服务消息交换协议，封装请求 / 响应在网络上传递。
  • REST：另一种更轻量的架构风格，基于 HTTP 资源 + 动词的无状态交互，常用于 SOA / 微服务的对外接口。
问题 2为何在「尽量不大改」前提下推荐 SOA 而非重构为微服务？8 分

公司既想互通又想控制成本。请结合 SOA 与微服务的四点区别（粒度、通信、交付、场景）说明为什么这里更适合 SOA。

参考答案
  • 粒度：SOA 服务粗粒度、服务数量少；微服务细粒度、小而不孤。当前是现存大块系统，粗粒度更贴合。
  • 通信：SOA 通过 ESB 统一消息总线交互；微服务多用统一协议（REST / RPC）直接互访。ESB 便于异构遗留系统转换，无需削平技术栈。
  • 交付：SOA 追求兼容原有系统、渐进集成；微服务追求快速独立交付。企业「不推倒重建」的诉求正是 SOA 的兼容定位。
  • 场景：SOA 面向企业级、强调治理与复用；微服务面向互联网、强调敏捷扩张。企业多系统异构、数据分散更宜 SOA。
问题 3服务注册表模式支持哪三个活动？说明「明确接口」与「粗粒度」设计原则的重要性。9 分

企业要具备服务治理能力，需引入服务注册表模式。请指出该模式的三个活动，并说明服务为何强调明确定义的接口与粗粒度。

参考答案
  • 服务注册表模式三大活动：服务注册（提供者公布功能）、服务位置（查询符合要求的服务）、服务绑定（利用服务合同开发代码并调用）。
  • 明确定义的接口：服务定义长期稳定、一旦公布不能随意改动，且不透露私有数据——保证调用方不因服务内部变更而失效，支撑松耦合。
  • 粗粒度：服务数量不宜过多、强调复用；依赖消息交互而非细粒度 RPC，减少网络调用与耦合，提升整体可维护性与性能。
