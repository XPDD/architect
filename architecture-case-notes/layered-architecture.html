▸ 核心要点
1N 层架构与分层

软件层次式体系结构是最通用的架构，也叫 N 层架构模式。大部分应用会分为四层：表现层（展示层）→ 中间层（业务层）→ 数据访问层（持久层）→ 数据层。

  • 表现层动态生成设计：基于 XML 的界面管理技术，可实现静态（灵活界面配置）、动态（界面动态生成、界面定制）。思路是用 XML 生成配置文件及界面元数据，按需生成界面元素。
2业务层框架（业务容器）

业务框架位于系统架构中间层，是实现系统功能的核心组件，采用容器形式便于功能开发、代码重用和管理。业务逻辑按 Domain Model — Service — Control 思想实现：

组件含义
Domain Model领域层业务对象，仅包含业务相关属性
Service业务过程实现的组成部分，是应用程序不同功能单元，靠良好接口和契约联系
Control服务控制器，服务之间的纽带，不同服务之间切换靠它实现

3数据访问层 — 5 种数据访问模式
模式要点
在线访问占用一个数据库连接，每个操作经此连接与后台数据源交互（如 pl/sql、navicat）
DAO标准 J2EE 设计模式，将底层数据访问操作与高层业务逻辑分离
DTO经典 EJB 设计模式，跨进程/网络边界传输数据的容器，不含业务逻辑，只做一致性检查和基本验证
离线数据模式以数据为中心，数据从数据源取出后按预定义结构存放，操作独立于后台连接/事务
O/R Mapping对象/关系映射，在「对象」与「关系型数据库记录」之间相互转换
4工厂模式 · 事务 · 连接池
  • 工厂模式：定义接口 DataAccess → 抽象类 AbstractDataAccess（公用方法）→ 具体实现（SQL Server / Oracle / MySQL）→ Factory 类根据数据库类型返回对应操纵类，实现自动切换。
  • 事务处理（JDBC）：连接默认 auto-commit 模式，每条 SQL 单独提交；要组合多 SQL 需屏蔽 auto-commit，最后统一调用 commit() 确认。
  • 连接池：用资源池解决资源频繁分配/释放；请求时先找空闲连接，无空闲则复用已分配连接；释放时若无使用者则放回连接池而非关闭。
5物联网三层架构
层次作用组成/技术人体类比
感知层识别物体、采集信息（解决数据获取问题）二维码、RFID、摄像头、GPS、传感器、M2M 终端、传感器网关皮肤和五官
网络层传递和处理信息（解决传输预处理问题）通信网+互联网融合、网络管理中心、信息中心、智能处理中心神经中枢和大脑
应用层实现广泛智能化（解决信息处理与人机交互问题）智能计算、云计算等，与行业需求深度融合社会分工

层次架构说人话：就是一个「分层蛋糕」——最上层接用户（表现层），中间管业务（业务层），下面管数据存取（数据访问层），最底是数据库。业务层里再套一个「业务容器」，里面三个角色：Domain Model 只装数据属性、Service 干活的单元、Control 当调度员。数据访问层五种方式记口诀：「在线 DAO，DTO 离线映射」。物联网三层用身体记：感知层=皮肤五官（采）、网络层=神经大脑（传）、应用层=社会分工（用）。

▸ 总结

层次架构分表现层/业务层/数据访问层/数据层四层；业务层用业务容器 + Domain Model—Service—Control；数据访问层 5 模式＝在线访问、DAO、DTO、离线数据、O/R Mapping；工厂模式靠 DataAccess 接口+Factory 类切库；物联网感知层(采)—网络层(传)—应用层(用)三层。重点掌握 N 层分层 + 业务容器图 + 物联网三层。
