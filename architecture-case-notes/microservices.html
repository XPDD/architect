▸ 核心要点
1微服务 vs 单体架构

微服务架构：把一个应用拆分为一组小型、独立的服务，每个服务围绕特定业务功能构建，通过轻量级通信机制（REST / RPC / 消息队列）相互协作。单体架构：整个应用作为一个单一单元构建和部署。

微服务优点
  • 灵活性和可扩展性：每个服务独立部署、扩展，系统更富弹性
  • 技术多样性：各服务可用不同技术栈，选最适合的
  • 易于理解和维护：小型聚焦，代码更易读、易开发、易分工维护
⇄
微服务缺点
  • 复杂性：分布式事务、服务发现、服务治理等复杂问题
  • 部署和测试：服务数量增加，部署测试更复杂
  • 运维成本：监控、日志收集、故障排查等工作更多

选型理由万能句：结合业务背景（高并发/快速迭代/独立扩容需求）→ 对比单体突出优势 → 强调独立部署与水平扩展 → 引用架构原则（高内聚低耦合、康威定律）。

2SOA vs 微服务（四点区别）
维度SOA微服务

通信通过 ESB 统一消息总线交互（重量级）统一协议（REST / RPC）直接互访，无需 ESB

场景面向企业级，强调治理与复用，适合庞大异构遗留系统面向互联网，强调敏捷扩张，适合快速轻量系统
3微服务拆分原则
  • DDD 领域驱动：按业务领域边界拆分，单一职责、低耦合高内聚；每个服务独立数据库。
  • 服务分层（范文6 结构）：基础服务层（网关/认证/权限/用户/IM/支付）+ 业务服务层（诊疗/订单/处方/病历）+ 工具服务层（定时/文件/日志/分布式事务）。
  • 容错设计：认证与用户分离——认证宕机不影响用户服务，容错更高。
  • 拆分代价：拆得越多，分布式事务与服务治理成本越高，切忌为拆而拆。
4微服务设计约束（4 类）
  • 个体约束：功能在业务域上相互独立，单一职责、低耦合。
  • 横向关系（服务间）：可发现性、可交互性，一般需要服务注册中心。
  • 纵向约束（服务与数据层）：数据存储隔离——数据是微服务私有资产，访问必须通过其 API，禁止直连对方数据表。
  • 全局分布式约束：故障发现时效性和根因精确性是核心诉求。
5微服务治理技术栈（拆开之后怎么管）
技术域代表产品核心作用
服务拆分DDD 领域驱动按业务领域边界拆，单一职责
注册发现Eureka / Nacos服务启动注册、按服务名查 IP/端口、心跳健康检查（Nacos 30 秒心跳、异常剔除）
配置中心Apollo / Nacos动态配置、免发版切换（日志开关/限流阈值）
API 网关Spring Cloud Gateway / Kong统一入口、路由、鉴权、限流
服务治理Hystrix / Sentinel熔断/降级/限流/负载均衡——雪崩防护核心，论文最亮技术点
可观测性SkyWalking/Jaeger · Prometheus · ELK/Loki链路追踪 + 指标监控 + 日志聚合三件套
服务网格Envoy Sidecar · Istio · mTLS治理下沉为平台基础设施，流量管理、零信任安全
容器化Docker + KubernetesDeployment/Service/Ingress/HPA 自动扩缩容
6熔断 vs 降级 vs 限流
①
熔断 — 别人坏了我不等
  • 依赖服务故障时快速失败返回备选，防止雪崩
  • Hystrix / Sentinel 断路器，节点故障返回兜底响应
②
降级 — 我主动砍功能
  • 主动牺牲非核心功能保核心（如双 11 关推荐、返回兜底数据）
③
限流 — 进门限量
  • 控制进入流量速率，防压垮（令牌桶 / 漏桶）
④
负载均衡
  • 将请求分发到多个实例（Feign + LoadBalancer）

8论文 / 案例答题套路
  • 三问分论点：①服务拆分（DDD）→ 解耦问题；②注册/配置/网关治理 → 管理难问题；③熔断降级限流 + 可观测性 → 雪崩问题。进阶加分：Istio 服务网格流量管理 + mTLS 零信任。
  • 每个技术点务必配：为什么选它 + 对比了什么 + 量化效果。
  • 结尾必写「不足与解决措施」（如熔断降级未用 Sentinel、分布式事务未用 Seata）——范文6 的失分点正是只写好处不写不足。
  • 通用结构：概念一句话 → 项目问题 → 方案取舍 → 具体技术 → 量化结果。

◆ 费曼

微服务说人话：就是把一个大应用按业务拆成一堆小服务，每个小服务只管一件事、自己带自己的数据库、能独立上线。好处是哪块火了就单独扩哪块、坏了只坏一块；代价是拆完一堆烂摊子要自己管——服务互相找不到（注册中心）、配置改一次要发版（配置中心）、入口要统一守（网关）、一个挂了不能连坐（熔断降级限流）、出问题要查得清（可观测）。考试就考三件事：为什么拆（vs 单体/SOA）、怎么拆（DDD + 4 约束）、拆完怎么管（治理技术栈）。口诀：熔断"别人坏了我不等"、降级"我主动砍功能"、限流"进门限量"。

▸ 总结

微服务＝一组小型独立服务，轻量级通信，围绕业务能力构建；选型理由＝独立部署/扩展/技术多样性 vs 分布式复杂性的取舍；SOA 四点区别＝粒度/通信(ESB vs REST/RPC)/交付/场景；拆分靠 DDD + 单一职责 + 数据存储隔离；4 约束＝个体/横向/纵向/全局；治理技术栈＝注册发现(Nacos)+配置中心+API 网关+熔断降级限流(Hystrix/Sentinel)+可观测+服务网格(Istio)+K8s。论文按"三问分论点"写，结尾必写不足与解决措施。
