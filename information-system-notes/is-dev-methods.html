▸ 核心要点
1结构化方法（SA + SD + SP）

由结构化分析(SA)、结构化设计(SD)、结构化程序设计(SP)三部分组成；精髓是自顶向下、逐步求精、模块化设计。

主要阶段：需求分析 → 概要设计 → 详细设计 → 编码实现 → 测试 → 部署。

特点：开发目标清晰化（用户第一）、开发工作阶段化、开发文档规范化、设计方法结构化（分析自顶向下、实现自底向上）。

不足：开发周期长、难以适应需求变化、很少考虑数据结构（面向数据流）。

工具：数据流图、数据字典、结构化语言、判定表、判定树。

2原型化方法（快速原型法）
  • 按是否实现功能：水平原型（行为原型，功能导航）vs 垂直原型（结构化原型，实现部分功能）。
  • 按最终结果：抛弃式原型 vs 演化式原型。
  • 优点：周期短、成本风险低、以用户为中心、能有效确认需求、满意度高。
  • 不足：开发环境要求高、管理水平要求高。
  • 适用：需求不明确、分析层面难度大而技术层面难度不大的系统。
3面向对象方法（OO）
  • 思想：客观世界由对象组成，对象属于某对象类。
  • 特点：复用性好；系统分析、设计、实现三阶段无「缝隙」（界限不明确）。
  • 不足：依赖面向对象技术；大型项目有局限，不能涉足系统分析以前的环节。
  • 结合使用：大型系统常「结构化自顶向下划分 + OO 自底向上开发」。
4面向服务方法（SOA）

将接口定义与实现解耦，催生服务和面向服务开发。核心：把系统分割成不同服务，每服务完成一项业务功能，服务间通过开放接口交互，实现服务提供者与调用者松耦合。优点：提高可复用性、信息资源共享、系统互操作性。

◆ 费曼

四种开发方法 = 四种「盖楼」方式：结构化像画图纸分阶段施工（自顶向下，稳但慢、怕改需求）；原型法像先搭个模型给客户看（快、适合需求不明确）；面向对象像用预制积木（可复用，但超大工程吃力）；SOA像点外卖（你只关心菜单接口，餐馆内部怎么改都影响不到你——松耦合）。

▸ 总结

结构化=SA+SD+SP，自顶向下逐步求精，缺点是周期长/怕变化/少考虑数据结构；原型法分水平/垂直、抛弃/演化，适合需求不明确；OO复用好、三阶段无缝隙，大型项目有局限；SOA=接口与实现解耦，松耦合。
