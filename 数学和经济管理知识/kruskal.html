▸ 核心要点
1三个基本概念
  • 权值：每条边上标的数字，代表这条边的「代价」（如修路费用）。例 AE=9 表示 A 村到 E 村修路花 9。
  • 生成树：从原图中挑出包含「全部顶点」且「连通、无环」的子图。n 个顶点的树恰好 n−1 条边。
  • 最小生成树（MST）：所有生成树中，权值之和最小的那一棵。
  • 题眼翻译：「最小生成树的权值之和」＝ 用 n−1 条边连通所有顶点且不绕圈，最省钱的方案花多少。
2Kruskal 算法思想

一句话：不断用当前最便宜的边，把两个还不连通的连通块连起来。

  • 全程维护的不是一棵树，而是一片森林（若干连通块）：初始 n 个孤立点 = n 个块。
  • 每成功选一条边 → 连通块数 −1；选满 n−1 条边 → 只剩 1 块 = 一棵树。
  • 决策只有一句：两端不连通 → 选边 + 合并；两端已连通 → 成环 → 跳过。
3为什么需要并查集（DSU）

每一步都要回答：这条边的两个端点，是不是已经连通了？并查集就是「记账本」，记录谁和谁已经在同一个连通块里，把「判断是否成环」和「合并两个集合」都做到近乎 O(1)。

4「初始化」到底做什么（易卡点）

初始时还没选任何边，任何两个顶点都不连通。所以规定：每个顶点各自成一个集合 —— 用「父节点指针」表示就是每个节点的父亲是它自己：

pa[A]=A pa[B]=B pa[C]=C pa[D]=D pa[E]=E pa[F]=F # Python self.pa = list(range(size)) # pa[i] = i // C++ 等价写法 vector<int> pa(size); iota(pa.begin(), pa.end(), 0);

pa[x] == x 说明 x 是根，一个根代表一个集合。初始 6 个顶点 = 6 个集合，就这一步。

5三个核心函数 + 完整模板
  • init：各自为集合（pa[i]=i）。
  • find：查根，配路径压缩 fa[x]=x?x:fa[x]=find(fa[x])。
  • union：fa[find(u)] = find(v)，把两棵树挂到一起。
int fa[N]; void init(int n){ for(int i=0;i<n;i++) fa[i]=i; } // 初始化：各自为集合 int find(int x){ return fa[x]==x ? x : fa[x]=find(fa[x]); } // 查根（路径压缩） int kruskal(){ init(n); sort(edges.begin(), edges.end()); // 按边权升序 int cnt=0, sum=0; for(auto &e : edges){ if(find(e.u)==find(e.v)) continue; // 同集合 → 成环 → 跳过 fa[find(e.u)] = find(e.v); // 不同 → 选边 + 合并 sum += e.w; if(++cnt == n-1) break; // 凑够 n-1 条边就停 } return sum; }

7正确性①：为什么「避环」是对的

若 u、v 已连通，说明已选的边里已存在一条 u→v 的路径，再加 (u,v) 就形成环；而树的定义是「连通且无环」——环上随便删哪条边图仍连通，所以这条边在任何生成树里都是冗余的。跳过它绝不会漏掉最优解。

8正确性②：割性质（贪心为何最优）

割性质：把顶点任意劈成两半（S ｜ 其余），若某个连通块完全落在 S 内，则横跨这个割的最小权边，一定可以安全地选入某棵 MST。

交换证明：设 MST 里没选跨割最小边 e。把 e 硬加进去 → 树里恰好出现一个环；e 一端在 S、一端在 T，原来那条 u→v 路径必须至少再跨割一次，设该跨割边为 f，则 w(e) ≤ w(f)。把 f 换成 e，环断开，仍是一棵生成树，权值不增。所以存在一棵含 e 的 MST，选它不亏。

人话：两个连通块之间迟早要架一座桥，架哪座都是架，为什么不架最便宜的？架贵的桥不会有任何额外好处。

9正确性③：归纳不变量
  • 不变量：每处理完一条边，已选边集始终是「某棵 MST 的子集」。
  • 初始：空集 ⊆ 任何 MST ✅
  • 每步：两端同块 → 跳过，集不变 ✅；两端不同块 → 该边是当前割的最小跨割边，由割性质某棵 MST 也含它 ✅
  • 结束：选了 n−1 条边 = 一棵生成树，且 ⊆ 某棵 MST → 它就是 MST ✅
10为什么「先排序」是必须的

按权从小到大扫描，保证「考虑一条边时，比它小的边已被尽量吸收」。这样两端首次分属不同连通块时，这条边恰好就是对应割的最小跨割边，割性质正好适用。若乱序处理，可能先选了贵桥，便宜桥反而因成环被扔掉 → 结果就错了。

11Kruskal vs Prim
维度KruskalPrim
思路多块同时长大，每次架最便宜的桥（选边）从单点长出一棵树，每次接最近的顶点
依赖边排序 + 并查集（避环）优先队列/数组 + 已选顶点集
适用稀疏图稠密图
复杂度O(E log E)O(V²) 或 O(E log V)

两者背后都是同一个割性质。

◆ 费曼

Kruskal 说人话：把村庄修路想成「捡最便宜的边」——先问最便宜的那条能不能用，能用就用，绝不放过便宜货；会绕圈的直接扔。并查集只是个记账本，随时回答「这两个村子现在是不是已经连在一起了」。它为什么最便宜？因为每两个还没连通的块之间迟早要架一座桥，既然架哪座都是架，那就架最便宜的——架贵的不会带来任何额外好处。所以从小到大挨个问一遍，便宜的全用上、贵货只在非用不可时才用，自然就是最省钱的连法。

▸ 总结

Kruskal＝按边权升序选边 + 并查集避环：初始化 pa[i]=i（各自成集合），每边用 find 判断两端是否同集合——不同则选边并 union，选满 n−1 条即得最小生成树。正确性靠割性质（跨割最小边必在某棵 MST 中）+ 交换论证 + 「已选边 ⊆ 某棵 MST」的归纳不变量；「先排序」是割性质适用的前提。复杂度 O(E log E)，稀疏图优于 Prim，二者同源割性质。
