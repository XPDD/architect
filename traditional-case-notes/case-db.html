数据库
【说明】

某医药销售企业因业务发展，需要建立线上药品销售系统，为用户提供便捷的互联网药品销售服务。系统除常规药品展示、订单、用户交流与反馈功能外，还需提供热销产品排名、评价分类管理等功能。通过对需求的分析，数据管理上初步决定采用关系数据库（MySQL）与数据库缓存（Redis）的混合架构。经过规范化设计之后，部分数据库表结构如下：

  • 供应商（供应商ID，供应商名称，联系方式，供应商地址）；
  • 药品（药品ID，药品名称，药品型号，药品价格，供应商ID）；
  • 药品库存（药品ID，当前库存数量）；
  • 订单（订单号码，药品ID，供应商ID，药品数量，订单金额）。
问题 1反规范化设计方法有哪些？用户查询商品信息应采用哪种？9 分

系统运行后数据访问性能较差。原因是规范化设计后关系表过于细分，造成大量多表关联查询影响性能。例如用户查询商品信息时需同时显示该药品信息、供应商信息、当前库存等。刘工建议采用反规范化设计改造药品关系的结构，修改后的药品关系为：药品（药品ID，药品名称，药品型号，药品价格，供应商ID，供应商名称，当前库存数量）。请用 200 字以内文字说明常见的反规范化设计方法，并说明用户查询商品信息应采用哪种方法。

参考答案

常见反规范化技术（5 种）：

  • 增加冗余列：在多个表中保留相同列，通过增加数据冗余减少或避免查询时的连接操作。
  • 增加派生列：增加由本表或其它表中数据计算生成的列，减少连接并避免计算或使用集合函数。
  • 重新组表：若许多用户需要查看两个表连接的结果数据，则把两表组成一个表来减少连接、提高性能。
  • 水平分割表：根据一列或多列数据值把数据放到多个独立表，用于表数据规模大、数据相对独立或需存放到多介质时。
  • 垂直分割表：将主键与部分列放到一个表、主键与其它列放到另一个表，查询时减少 I/O 次数。

用户查询商品信息采用的是增加冗余列的方式（把供应商名称、当前库存数量冗余到药品表中）。

问题 2解决反规范化数据不一致问题的三种常见方法，该系统应采用哪种？9 分

王工认为，反规范化设计可提高查询性能，但必然会带来数据不一致问题。请用 200 字以内文字说明在反规范化设计中解决数据不一致性问题的三种常见方法，并说明该系统应采用哪种方法。

参考答案

三种常见方法：

  • 批处理维护：对复制列或派生列的修改积累一定时间后，运行一批处理作业或存储过程进行修改——仅适合实时性要求不高的场景。
  • 应用逻辑：必须在同一事务中对所有涉及的表进行增、删、改操作。用应用逻辑实现完整性风险较大，因为同一逻辑须在所有应用中维护，容易遗漏、不易维护。
  • 触发器：对数据的任何修改立即触发对复制列或派生列的修改。实时，且处理逻辑只出现在一个地方，易于维护，通常是较好的办法。

该系统应采用触发器。

问题 3实现热销药品排名应选哪种 Redis 数据类型？说明 Redis 与 MySQL 实时同步的常见方案。7 分

系统采用 Redis 实现特定功能（如当前热销药品排名），并将药品关系数据放入内存以提高商品查询性能，但必然会造成 Redis 与 MySQL 数据实时同步问题。

(1) Redis 的数据类型包括 String、Hash、List、Set 和 ZSet 等，请说明实现当前热销药品排名功能应该选择使用哪种数据类型。

(2) 请用 200 字以内文字解释说明解决 Redis 和 MySQL 数据实时同步问题的常见方案。

参考答案

(1) 选 ZSet（Sorted Set / 有序集合）——按分数（销量）自动排序，天然适合排行榜/排名。

(2) Redis 与 MySQL 实时同步常见方案：

  • 实时同步（强一致）：查询缓存 hit 不到再从 DB 查询并写入缓存；更新缓存时先更新数据库，再将缓存设置过期（建议直接设置过期，而非更新缓存内容）。
  • 异步队列：对并发程度较高的场景，采用 Kafka 等消息中间件处理消息的生产与消费。
  • canal 工具：模拟 MySQL slave/master 同步机制，监控 DB binlog 日志更新触发缓存更新，可解放程序员、减少工作量，但有一定局限性。
  • UDP 自定义函数 / 触发器：对 MySQL API 编程，利用触发器进行缓存同步。
