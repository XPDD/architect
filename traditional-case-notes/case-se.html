软件工程
【说明】

某公司欲建设一个房屋租赁服务系统，统一管理房主和租赁者的信息，提供快捷的租赁服务。系统主要功能描述如下：

  • 1. 登记房主信息：记录房主的姓名、住址、身份证号、联系电话等，并写入房主信息文件。
  • 2. 登记房屋信息：记录房屋地址、类型（平房、带阳台楼房、独立式住宅等）、楼层、租金及状态（待租赁/已出租），写入房屋信息文件。一名房主可登记多套待租赁房屋。
  • 3. 登记租赁者信息：记录租赁者姓名、性别、住址、身份证号、电话等，并写入租赁者信息文件。
  • 4. 安排看房：已登记的租赁者可从待租赁房屋列表查询信息，可提出看房请求，系统安排看房。每次看房生成一条看房记录并写入看房记录文件。
  • 5. 收取手续费：房主登记完房屋后，系统生成一份费用单，房主按费用单交纳相应费用。
  • 6. 变更房屋状态：当租赁者与房主达成租房或退房协议后，房主向系统提交变更请求，系统据请求修改房屋信息文件。

  • 外部实体：E1=房主，E2=租赁者。
  • 加工：P1=登记房主信息，P2=登记房屋信息，P3=登记租赁者信息，P4=查询租赁房屋信息，P5=安排看房，P6=变更房屋状态。
  • 数据存储：D1=房主信息文件，D2=租赁者信息文件，D3=房屋信息文件，D4=看房记录文件。

问题 3说明「实体 vs 类」的区别，以及 Essential / Real Use Case 的区别。8 分

(1) 信息工程方法中的「实体（entity）」与面向对象方法中的「类（class）」之间有哪些不同之处？

(2) 在面向对象方法中通常采用用例（Use Case）捕获系统功能需求。用例可按不同层次划分，Essential Use Cases（抽象用例）与 Real Use Cases（基础用例）有哪些区别？

参考答案
  • (1) 实体 vs 类：实体用于数据建模，而类用于面向对象建模；实体只有属性，而类有属性和操作。
  • (2) 抽象用例 vs 基础用例：基础用例（Real Use Case）是实实在在与用户需求有对应关系的用例，是从用户需求获取的渠道得到的；抽象用例（Essential Use Case）是从基础用例中抽取的用例的公共部分，是为了避免重复工作、优化结构而提出的用例。
